# WYNOS Merchant Android — QA audit (2026-10-14)

**PR:** #1193 — `feat/merchant-native-android-foundation` (Draft). **Release decision: NO-GO.**

## Scope and evidence

Reviewed Android Kotlin/Jetpack Compose implementation against the merchant web's source-of-truth TypeScript and supporting Supabase SQL contracts. Inspected authentication/data API, order/payment state, business publishing, image uploads, history, menu/categories, schedule, Stripe display, printing, and user roles. Existing CI builds `assembleDebug` and executes `testDebugUnitTest`, plus a static contract verifier.

**Limits:** CI's development APK contains no live Supabase URL/key. No credentialed test-merchant E2E, instrumented real-device UI, payment/refund, FCM background push, storage/RLS penetration test, or actual printer test has been performed. Passing compilation alone must not be reported as 100% functionality.

## Confirmed code defects fixed in this QA pass

| ID | Severity | Defect | Fix |
| --- | --- | --- | --- |
| QA-001 | P1 | Store publishing called `merchant_store_readiness` while its UI and production-readiness trigger use `food_store_publish_readiness`; the criteria may disagree. | Publishing now calls `readiness(storeId)` and shows missing criteria. |
| QA-002 | P1 | Opening a data-dependent screen during another network request silently skipped its fetch due to the global busy guard. | A pending page fetch is dispatched after the active request completes. |
| QA-003 | P1 | Menu/store/notification PATCH or DELETE could report success after zero rows were updated (common with missing records/RLS). | PostgREST single-row writes request representation and reject empty responses; bulk mark-all-read is exempt. |
| QA-004 | P1 | Orders over the first 100 had a warning but no working load-more action. | Added native order paging and a load-more action with ID deduplication. |
| QA-005 | P2 | The 24h completed-order cutoff had no native automated boundary tests. | Extracted pure time-window predicate and added JUnit tests for boundary, future, cancelled and active statuses. |

Static contract checks are extended to guard fixes to readiness, paging, image paths and RLS write semantics.

## Verification procedure / gate

- `node merchant-android/tools/verify-contracts.mjs` — static contract assertions.
- `gradle :app:assembleDebug :app:testDebugUnitTest` — debug compilation plus JUnit suite on GitHub Actions.
- Retest the current PR head after every code change (do not rely on a successful older run).
- Run manual E2E on at least one Android test phone with an **isolated, authorized merchant test account** and seeded test orders. Do not operate on real paid orders during development QA.
- Security review storage policies/RLS; run tests with owner, manager, orders-only and unrelated store user.
- Do not mark features complete until a passing API + UI scenario is recorded in [FEATURE_PARITY.md](FEATURE_PARITY.md).

**No production merges, migrations, or deployments made in this QA audit.**
