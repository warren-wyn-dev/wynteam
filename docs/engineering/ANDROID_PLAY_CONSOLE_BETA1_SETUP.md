## 4. Play Console declarations before closed/production

1. **App content / Policy:** public Privacy Policy, Data safety (collection/sharing for email/account/profile/posts/media/messages/push tokens and vendor SDK behavior), accurate Ads declaration, Target audience and content, Content rating and news/other relevant declarations.
2. **Account deletion:** users can initiate deletion inside the app and from a **public web URL** without reinstalling the app. Existing Android app has a deletion UI, but `docs/engineering/ANDROID_RELEASE.md` identifies possible retained Supabase Storage photos: **investigate/fix before declaring complete**; preserve necessary disclosures and comply with deletion rules.
3. **Social UGC:** tested reporting of users/posts, blocking, moderators and responses, Terms acceptance before posting, community guidelines, abuse escalation.
4. **Child safety:** public standards against CSAE, in-app reporting, CSAM response, child safety legal compliance and a named contact. This applies to the **Social category**, even if children are not the intended audience.
5. **App access:** credentials, invite code and *English* reviewer instructions; usable repeatedly, in any region, without expiring OTP. Enter them in the Console only.
6. **Store settings:** category Social, contact email, permitted countries/regions (owner decision), app pricing (owner decision).
7. **Personal account testing:** if the owner uses a **personal Play developer account created after 2023-11-13**, plan at least **12 continuously opted-in closed testers for 14 days** before applying for production access. Internal testing supports up to 100 testers and can precede the closed-test setup.
8. **Policy consistency:** screenshots, website, privacy/child-safety/deletion resources, and data-handling statements must match actual app behavior.

## 5. Signed AAB preparation — no execution authorized

The repo already has `.github/workflows/android-release.yml` (manual only, **main** only, environment `android-release`). It expects four upload signing key secrets plus six Supabase/Firebase client configuration values. **The previous CI `bundleRelease` output is not a signed Play upload artifact.**

Before requesting approval to build a signed bundle:
- Check if there is already an upload key; **never create a second key blindly**, leak signing material, export secret values or commit a key file.
- Verify release-required secret *names are configured* (not values) in GitHub Actions and that the `android-release` environment is protected.
- Verify Firebase Android registration for `io.wyn.wyn`, FCM, and Google OAuth client SHA-1; current Android `signInWithGoogle()` explicitly returns a not-ready message.
- Review and merge PR #1157 separately after CI, security review and Founder approval; only then can the existing manual signed release workflow run from `main`.
- Run release workflow only with separate authorization for **artifact creation**; compare certificate SHA fingerprints, signature verification, package, target API, version code, `mapping.txt`, hashes and real-device QA.
- Upload the signed AAB to any Play track **only with its own approval**. There is no submitted build from this preparation task.
- App Links domain verification: the website's assetlinks route uses Play signing SHA-256 fingerprints from `ANDROID_APP_SHA256_FINGERPRINTS`; a production web setting/deploy requires a separate approval.
