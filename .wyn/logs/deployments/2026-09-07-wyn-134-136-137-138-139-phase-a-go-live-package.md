## Rollback Plan

### WYN-134 (DM New Message Notification)
- **Database**: purely additive ต่อ `notifications`/trigger ใหม่ + re-definition ของ `mark_conversation_read()` (เพิ่ม branch ใหม่ ไม่ลบของเดิม, ยืนยันด้วย regression test ว่า behavior เดิมยังอยู่ครบ) — rollback แบบไม่ลบข้อมูล: `drop trigger messages_notify_new_message on public.messages;` หยุดการสร้าง notification ใหม่ทันที (ไม่กระทบ notification ที่มีอยู่แล้ว/mark_conversation_read() ยังทำงานปกติแค่ branch ใหม่จะไม่มีอะไรให้เคลียร์)
- **Edge Function**: ไม่มี Instant Rollback ในตัว Supabase CLI — ถ้าต้องถอย ให้ deploy function เวอร์ชันก่อนหน้าซ้ำผ่าน `deploy-edge-functions.yml` (เลือก branch/commit ก่อน WYN-134)
- **Web**: ไม่มี UI ใหม่ที่ต้องถอย (แค่ 1 entry ใหม่ในลิสต์ notification เดิม)

### WYN-138 (DM Edit + Pin)
- **Database**: additive ล้วน (`edited_at` column ใหม่ + `message_pins` table ใหม่) ยกเว้น `delete_message()`/`edit_message()` ถูก re-define — rollback แบบไม่ลบข้อมูล: ปิด RLS insert/update บน `message_pins` ชั่วคราวถ้าต้องหยุดการปักหมุดทันที (ข้อมูลเดิมไม่หาย) หรือ `drop table message_pins` ถ้ายอมรับให้ pin ที่มีอยู่หายไป (ไม่กระทบ `messages` เอง เพราะ `edited_at` เป็นแค่ nullable column)
- **Web**: Vercel Instant Rollback หรือ `git revert` แล้ว trigger `deploy-web.yml` ใหม่

### WYN-139 (DM Presence)
- **Database**: purely additive (`user_presence` table ใหม่ทั้งตาราง ไม่แตะ `profiles`/ตารางเดิมเลย) — rollback ง่ายที่สุดในชุดนี้: `drop table user_presence cascade;` ปลอดภัย 100% ไม่กระทบตารางอื่นใดเลย
- **Web**: Vercel Instant Rollback หรือ `git revert` แล้ว trigger `deploy-web.yml` ใหม่

### WYN-136 (Club Invite Link)
- **Database**: additive ล้วน (2 ตารางใหม่ + 4 RPC ใหม่ ไม่แตะ `clubs`/`club_members` เดิมเลยนอกจาก `insert ... on conflict` ผ่าน RPC) — **ความเสี่ยงจริงคือ semantics**: ทางเลือก A ทำให้ Private Club เข้าได้ทันทีผ่านลิงก์ที่หลุด — rollback ที่เร็วที่สุดถ้าเกิดปัญหาจริง (ลิงก์หลุดสู่สาธารณะโดยไม่ตั้งใจ) คือ **revoke ลิงก์นั้นเจาะจงทันทีผ่าน UI/RPC `revoke_club_invite_link()`** โดยไม่ต้องแตะ schema เลย ถ้าต้องปิดฟีเจอร์ทั้งหมด: `revoke execute on function public.redeem_club_invite_link(text) from authenticated;` หยุดการ redeem ใหม่ทันทีโดยลิงก์/ข้อมูลเดิมไม่หาย
- **Web**: Vercel Instant Rollback หรือ `git revert` แล้ว trigger `deploy-web.yml` ใหม่

### เกราะป้องกันร่วม (WYN-136/138/139)
Staged-rollout gate (`isDeveloperAccount()`) เป็นเกราะสำคัญที่สุดสำหรับ 3 ใน 4 task นี้ — ตราบใดที่ยังไม่เปิดให้ผู้ใช้ทั่วไป ความเสี่ยงจริงต่อผู้ใช้จริงเกือบเป็นศูนย์ วิธีที่เร็ว/ปลอดภัยที่สุดถ้าพบปัญหาหลัง deploy คือลบ `@warren`/`@wynos_online` ออกจาก `developer_accounts` ชั่วคราวผ่าน SQL Editor เพื่อหยุดผลกระทบทันทีโดยไม่ต้อง rollback โค้ด/DB เลย — **WYN-134 ไม่มีเกราะนี้** (ตั้งใจไม่ gate) จึงเป็น task เดียวที่ผู้ใช้ทั่วไปสัมผัสทันทีหลัง deploy — เหตุผลที่ QA/Design ยืนยันว่าเข้าเกณฑ์ข้อยกเว้นได้แล้ว (ปิด known gap ของฟีเจอร์เดิม ไม่ใช่ฟีเจอร์ใหม่)

## สิ่งที่ AI Deploy & DevOps รอบนี้ **ไม่ได้ทำ** (ยืนยันตามข้อจำกัดที่กำหนดไว้)

- **ไม่ได้ apply migration SQL ใดๆ ต่อ Supabase production เลย** — ตรวจสอบแล้วว่าไม่มี `SUPABASE_*` credential ใดๆ ในเครื่อง และไม่มี Supabase Management API access
- **ไม่ได้ merge branch เข้า `main`** และ **ไม่ได้เปิด PR** — session นี้ไม่มี `gh` CLI/GitHub tool ให้เรียกใช้
- **ไม่ได้ trigger `deploy-web.yml`** หรือ **`deploy-edge-functions.yml`** — ไม่มีสิทธิ์เข้าถึง GitHub Actions ในรอบนี้
- **ไม่ได้ rollback ใดๆ** — ไม่มีเหตุต้อง rollback (ยังไม่ deploy จริง)
- **ไม่พบ credential/เครื่องมือใดๆ ที่เข้าถึง production จริงได้ในรอบนี้** — ไม่มีอะไรต้องรายงานเป็นข้อกังวลด้านความปลอดภัย
