# WYNOS v1.0.0 Beta3 — Future Ideas

> วันที่: 2026-09-03
> ตามข้อ 0 ของ Beta3: ไอเดียที่พบระหว่างทาง **บันทึกไว้ ห้าม implement**
> ทุกข้อในไฟล์นี้ **ยังไม่ได้ทำ** และต้องรอ Founder สั่งก่อนเสมอ

---

## A. ไอเดียที่ **ไม่ใช่** ฟีเจอร์ใหม่ — เป็นงานคุณภาพที่ Beta3 เลือกไม่ทำ

จัดไว้ก่อนเพราะข้อพวกนี้ทำได้เลยถ้า Founder สั่ง โดยไม่ขัดกฎ "ห้ามเพิ่มฟีเจอร์"

### A-1 · ซ่อม supabase test fixture 5 ตัวที่ค้างแดง

`wyn_041`, `wyn_043`, `wyn_051`, `wyn_052`, `wyn_054_055` fail เพราะ fixture สร้าง profile ที่ username เป็น
`'admin'` / `'moderator'` ซึ่งชน constraint `profiles_username_not_reserved` ที่เพิ่มมาทีหลัง
เปลี่ยน username ใน fixture คือแก้ทั้งหมดที่ต้องทำ — ไม่แตะโค้ดผลิตภัณฑ์เลย

**ทำไม Beta3 ไม่ทำ:** ไม่เกี่ยวกับ Post/Feed/Performance ที่ Founder สั่งมา และการแก้ test ที่ตัวเองไม่ได้ทำพัง
ระหว่างงาน polish ทำให้แยกไม่ออกว่า suite ที่เขียวขึ้นมาจากอะไร
**ผลถ้าไม่ทำ:** suite ที่แดงเป็นปกติคือ suite ที่คนเลิกอ่าน — และครั้งหน้าที่มันแดงเพราะของจริง จะไม่มีใครสังเกต

### A-2 · ลบ `wyn_038_view_counting_test.sh` หรือเขียนใหม่

ความคาดหวังของ test นี้ถูกแทนที่โดย WYN-083 ซึ่งเปลี่ยนกติกาการนับ view ไปแล้ว
และ `wyn_083_view_count_owner_and_repeat_test.sh` ที่ครอบพฤติกรรมปัจจุบัน **ผ่าน**
`wyn_038` จึงเป็น test เก่าที่ถูก supersede — ควรลบหรือเขียนใหม่ให้ตรงพฤติกรรมจริง

### A-3 · Profile header เลื่อนหายไปพร้อม tab content

`ViewProfileScreen` เป็น `Column` + `Expanded(TabBarView)` — header (avatar / bio / ปุ่ม / TabBar) จึงตรึงอยู่
มีแค่เนื้อในแท็บที่เลื่อน ต่างจาก Post Detail ที่ Founder สั่งให้ทุกอย่างเลื่อนต่อเนื่องกัน

**ทำไม Beta3 ไม่ทำ:** ข้อ 5 พูดถึง **Post Detail** เท่านั้น ไม่ได้พูดถึง Profile
และการเปลี่ยนเป็น `NestedScrollView` กระทบ 3 แท็บ + pull-to-refresh + `AutomaticKeepAlive` + การรักษาตำแหน่ง scroll
ที่เพิ่งแก้ใน Beta3 พร้อมกันทั้งหมด — เป็นความเสี่ยง regression ที่ไม่คุ้มถ้าไม่ได้สั่ง
**ต้องขออนุมัติก่อน**

### A-4 · เปลี่ยน pagination จาก offset เป็น cursor

ทุกลิสต์ในแอปใช้ `range(from, to)` ซึ่งเป็นต้นตอของ "แถวซ้ำที่รอยต่อหน้า" โดยธรรมชาติ
Beta3 กันอาการไว้ด้วย `_seenKeys` ทุกลิสต์แล้ว (ปลอดภัย ใช้งานได้จริง) แต่ไม่ได้แก้ที่ราก

Cursor pagination (`created_at < ?` + tie-break ด้วย `id`) แก้ที่รากและยังไม่ต้องนับ offset ที่แพงขึ้นเรื่อย ๆ
**ทำไม Beta3 ไม่ทำ:** ข้อ 8 เขียนไว้ตรง ๆ ว่า *"ห้ามสร้างระบบ pagination ใหม่ถ้าของเดิมใช้ได้"* — ของเดิมใช้ได้แล้ว

### A-5 · แก้ RLS ของ `drop_images` ให้ตรวจต่อโพสต์ ไม่ใช่ต่อรูป

ดู security audit H-1 — `EXPLAIN` แสดง subplan ยิง 24 ครั้งเพื่อตรวจ 8 คำตอบ
ไม่ใช่ช่องโหว่ (คำตอบถูกเสมอ) เป็นเรื่องประสิทธิภาพล้วน
**ต้องแตะ RLS policy → ต้องขออนุมัติ Founder เสมอ**

### A-6 · Crash reporter

`ErrorWidget.builder` แสดงกล่อง error ที่อ่านรู้เรื่องใน release แต่ไม่มีใครได้รับรายงาน
ความผิดพลาดในมือผู้ใช้จริงจึงหายไปเงียบ ๆ — ยกมาจาก Beta2 audit ยังไม่ได้แก้

### A-7 · โดเมนจริงสำหรับ share link

`dropShareLink()` ยังคืน `https://wyn.app/drop/$id` ซึ่งไม่มีจริง ปุ่มแชร์จึงส่งลิงก์ที่เปิดไม่ได้
**ต้องรอ Founder ยืนยันโดเมนก่อน**

## B. ไอเดียที่ **เป็นฟีเจอร์ใหม่** — ห้ามทำจนกว่าจะสั่ง

### B-1 · ใช้ `drop_images.image_width/image_height` ที่มีอยู่แล้ว

WYN-093 เขียนขนาดของ **ทุกรูป** ลง `drop_images` ไว้ตั้งแต่ตอนสร้างโพสต์ แต่ยังไม่มีใครอ่านเลยสักคน —
ทั้งระบบใช้แค่ `drops.image_width/height` ซึ่งเป็นขนาดของ **รูปแรก** เท่านั้น

ถ้าอ่านของจริง: gallery ใน Post Detail จะปรับสัดส่วนตามรูปที่กำลังดูอยู่ได้ แทนที่จะใช้สัดส่วนของรูปแรกกับทุกรูป
**ทำไมไม่ทำใน Beta3:** สัดส่วนที่เปลี่ยนระหว่างปัดทำให้หน้ากระโดด ซึ่งขัดกับ "Smooth" ที่ Founder สั่ง
และเป็นการตัดสินใจด้าน UX ใหม่ ไม่ใช่การแก้ของเดิม

### B-2 · Skeleton สำหรับรูปที่มีสัดส่วนล่วงหน้า

ตอนนี้ placeholder ระหว่างโหลดรูปเป็นบล็อกสีเรียบในกล่องที่มีสัดส่วนถูกต้องแล้ว (ไม่มี layout shift)
ทำให้สวยกว่านี้ได้ (shimmer / blurhash) แต่นั่นคืองานใหม่ ไม่ใช่การแก้ของเดิม

### B-3 · Prefetch รูปของโพสต์ถัดไปใน feed

Beta3 ลดจำนวน request ลงแล้ว แต่ไม่ได้แตะ *จังหวะ* ของการโหลดรูป
การ prefetch รูปที่กำลังจะเข้า viewport เป็นระบบใหม่ ต้องคิดเรื่อง memory / data ของผู้ใช้ให้ครบก่อน

### B-4 · Persist โหมด feed ที่เลือกไว้

ตอนนี้ feed กลับไปเป็น "สำหรับคุณ" ทุกครั้งที่เปิดแอป — เป็นการตัดสินใจของ Design spec ("ค่าเริ่มต้น...เสมอทุกครั้งที่เปิดแอป")
ไม่ใช่บั๊ก ถ้าจะเปลี่ยนต้องเป็นคำสั่งจาก Founder

### B-5 · Pull-to-refresh ที่ Post Detail

หน้า Detail โหลดครั้งเดียวตอนเปิด ไม่มีทางดึงคอมเมนต์ใหม่โดยไม่ปิดแล้วเปิดใหม่ — เป็นฟีเจอร์ใหม่

## C. สิ่งที่ **ตัดสินใจแล้วว่าจะไม่ทำ** พร้อมเหตุผล

| เปลี่ยน peek carousel ของ Feed ให้เป็น `PageView` เหมือน Detail | ทั้งสอง pattern ถูกต้องในบริบทของตัวเอง: Feed = "ปัดผ่านเร็ว ๆ เห็นว่ามีอีก", Detail = "ดูทีละรูปให้เต็ม" |
