## ความต่างที่สังเกตได้จากคลิป

WYNOS ตอนนี้: ทุกการ์ดรูปกว้างเท่ากันตายตัว (82% ของคอลัมน์) เห็นรูปถัดไปโผล่ได้แค่ทางขวา รูปก่อนหน้า
ไม่เคยโผล่ทางซ้าย และไม่มีรูปไหนเปลี่ยนขนาดเลยไม่ว่าจะอยู่ตรงกลางจอหรือไม่

Threads: รูปที่อยู่ตรงกลาง (กำลังดู) เด่นกว่ารูปข้างเคียงอย่างชัดเจน รูปที่ยังไม่ถึงคิว/ผ่านไปแล้ว
เล็กลง เห็นโผล่ได้ทั้งสองข้างพร้อมกัน (ยกเว้นรูปแรกสุดที่ไม่มีรูปก่อนหน้า)

## Screen

`PostImageCarousel` (`core/widgets/post_media.dart`) — จุดเดียวที่ทั้ง 3 หน้าใช้ร่วมกัน: การ์ดฟีด Home
(ผ่าน `HomeFeedImagePeekCarousel`), Drop Detail (ผ่าน `DropImageGallery`), Club (`ClubPostCard`)

## Purpose

ทำให้รูปที่ "อยู่ตรงกลาง/กำลังดู" เด่นกว่ารูปข้างเคียงระหว่างเลื่อน โดยไม่เปลี่ยน logic การ snap/fling/
รายงานตำแหน่งที่มีอยู่แล้ว และไม่เปลี่ยนขนาด/ตำแหน่งของรูปแรกที่จุดพัก (ยังคง 82% เท่าเดิมทุกประการ)

## User Flow

ไม่เปลี่ยน — ลาก/fling ทำงานเหมือนเดิมทุกจุด แค่รูปที่ไม่ใช่รูปที่กำลังโฟกัสจะเล็กลงระหว่างเลื่อน

## Components

**วิธีทำ**: ไม่แตะ `ListView`/`ScrollController`/`_CardSnapPhysics` เดิมเลย (ตำแหน่งการ snap/fling/
รายงาน index ยังคำนวณจาก stride เดิมทุกประการ — คือเหตุผลที่เทสต์เดิมทั้ง 5 ตัวผ่านโดยไม่ต้องแก้)
เพิ่มแค่ `Transform.scale` รอบการ์ดแต่ละใบ คำนวณจากระยะห่างของตำแหน่งเลื่อนปัจจุบันกับตำแหน่งพักของ
การ์ดใบนั้น (`distance`, หน่วยเป็น "จำนวน stride"):

- `distance == 0` (การ์ดที่กำลังอยู่ตรงกลาง) → `scale = 1.0` (ขนาดเท่าเดิมทุกประการ ไม่มีอะไรใหญ่ขึ้นกว่าเดิม)
- `distance >= 1` (การ์ดที่ห่างออกไปตั้งแต่ 1 การ์ดขึ้นไป) → `scale = postCardPeekScale` (ค่าคงที่ใหม่)
- ระหว่างนั้น → ไล่ระดับเชิงเส้นต่อเนื่อง (ไม่กระตุกเปลี่ยนขนาดทีเดียว)

ทำไมไม่ทำให้การ์ดตรงกลาง "ขยายใหญ่กว่า 82% เดิม": 82% ที่มีอยู่คือขนาดที่ Founder อนุมัติไว้แล้วเมื่อ
2026-09-03 ("รูปต้องเรียงกันเป็นการ์ดนะ") การขยายเกินนั้นเสี่ยงชนขอบจอ/เพดานความสูง (WYN-071) โดยไม่จำเป็น
— แค่ทำให้ "รูปข้างเคียงเล็กลง" ก็ได้ผลต่างที่เห็นชัดเหมือนในคลิปแล้ว

**เหตุผลที่ไม่ทำแบบ "รูปข้างเคียงแคบลงจริง (เปลี่ยนความกว้างที่ประกาศ)"**: ทดลองแล้วพบว่าถ้าให้ความกว้าง
จริงของการ์ดเปลี่ยนตามระยะห่าง จะทำให้ตำแหน่งสะสมของการ์ดถัดไปเลื่อนตามไปด้วย (เพราะ `ListView` วางการ์ด
ถัดไปต่อจากความกว้างจริงของการ์ดก่อนหน้าเสมอ) ทำให้ตำแหน่งจุดพักไม่ตรงกับ stride คงที่ที่ physics คำนวณไว้
อีกต่อไป — ต้องรื้อ physics ทั้งชุดใหม่และเสี่ยงบั๊กสูงกว่ามาก `Transform.scale` (ปรับแค่ภาพที่วาด ไม่กระทบ
พื้นที่ที่ layout จองไว้) ให้ผลลัพธ์ที่ตาเห็นใกล้เคียงกันโดยไม่ต้องแตะ physics เลย

## Interactions

ไม่เปลี่ยน — snap ทีละการ์ด, flick ทำงานเหมือนเดิม, `onIndexChanged` รายงานถูกเหมือนเดิม, tap โดนตำแหน่ง
ที่เห็นจริง (transform สเกลผลต่อ hit-test ตามภาพที่วาดโดยอัตโนมัติ)

## States

ไม่มี state ใหม่ — `scale` คำนวณสดจากตำแหน่งเลื่อนทุกเฟรมระหว่างลาก ไม่เก็บเป็น field แยก

## Responsive Behavior

ทดสอบที่ความกว้างจอต่างกัน (320/390/430) — สัดส่วน 82%/scale เป็นเปอร์เซ็นต์ของความกว้างแถวเสมอ

## Accessibility

ไม่กระทบ Semantics เดิม — `allowImplicitScrolling = false` และ label ต่อการ์ดยังคงเดิมทุกจุด

## Design Rules

- ห้ามเปลี่ยนขนาด/ตำแหน่งของการ์ดที่จุดพัก (`distance == 0`) จาก 82% เดิม
- ห้ามแตะ `_CardSnapPhysics`/stride/`_updateIndex` — งานนี้เพิ่มเลเยอร์ภาพเท่านั้น
- ห้ามแตะ caller ทั้ง 3 จุด (`home_feed_image_peek_carousel.dart`/`drop_image_gallery.dart`/
  `club_post_card.dart`) — API ของ `PostImageCarousel` ไม่เปลี่ยน

## Handoff

1. `core/widgets/post_media.dart` — เพิ่มค่าคงที่ `postCardPeekScale` เพิ่ม `Transform.scale` รอบการ์ด
   ในแต่ละ `itemBuilder` คำนวณจากระยะห่างจากตำแหน่งเลื่อนปัจจุบัน ให้ `NotificationListener` เดิม
   trigger การ rebuild ต่อเนื่องระหว่างลาก (ไม่ใช่แค่ตอน index เปลี่ยน)
2. เทสต์เดิม 5 ตัวใน `post_media_test.dart` ต้องผ่านโดยไม่ต้องแก้ (พิสูจน์ว่าไม่กระทบ physics เดิม)
   เพิ่มเทสต์ใหม่ยืนยันพฤติกรรม scale: การ์ดตรงกลาง scale เท่าเดิม, การ์ดข้างเคียง scale เล็กลงจริง,
   ไล่ระดับต่อเนื่องระหว่างลาก ไม่กระตุก
3. `flutter analyze` + `flutter test` ผ่านครบ
