## Screen

- `HomeDropCard` (`app/lib/features/home/presentation/widgets/home_drop_card.dart`) — ใช้ในฟีด Home
  ทุกแท็บ, 3 แท็บของ Profile, hashtag feed
- `HomePopCard` (`app/lib/features/home/presentation/widgets/home_pop_card.dart`) — **อยู่ในสโคปด้วย**
  Founder อนุมัติเป็นข้อยกเว้นของกติกา "ห้ามแก้ไฟล์ Pop" เฉพาะไฟล์นี้ (ดูท้ายเอกสาร)

## Purpose

ทำให้ทุกองค์ประกอบในโพสต์เริ่มที่แนวเดียวกัน (แนวชื่อผู้โพสต์) แทนที่จะชิดขอบจอคนละแนวกับหัวโพสต์
— ตรงตามไฟล์อ้างอิงที่อนุมัติแล้ว และตรงกับที่ Founder ชี้ยืนยันด้วยภาพ

## User Flow

ไม่เปลี่ยน — ทุกปุ่ม ทุก gesture (แตะการ์ดเปิด Detail, double-tap ถูกใจรูป, ปัดรูป, กดปุ่ม ⋯) ทำงาน
เหมือนเดิมทุกประการ งานนี้เปลี่ยนเฉพาะตำแหน่งการวาง

## Components — โครงใหม่ (ค่าอ้างอิงบนจอ 390)

```
Padding(vertical: 16)
├─ Padding(horizontal: 24) → แถว "รีโพสต์โดย @x · เวลา"   ← อยู่นอกสองคอลัมน์ บนสุด
└─ Row
   ├─ Padding(left: 24) → Avatar 40px + วงแหวน sapphire 20%
   ├─ SizedBox(width: 14)
   └─ Expanded → คอลัมน์เนื้อหา (เริ่มที่ x = 78)
      ├─ Padding(right: 24) → ชื่อ + verified + เวลา/สถานที่ + ปุ่ม ⋯ (ชิดขวา)
      ├─ Padding(right: 24) → ข้อความโพสต์ + แฮชแท็ก
      ├─ (ไม่มี right padding)  → รูป — ล้นถึงขอบจอขวา
      ├─ Padding(right: 24) → แถวคนถูกใจ
      ├─ Padding(right: 24) → แถวปุ่ม ถูกใจ/คอมเมนต์/รีโพสต์
      └─ Padding(right: 24) → คอมเมนต์เด่น
```

### ค่าที่เปลี่ยนจากของเดิม

| จุด | เดิม | ใหม่ |
|---|---|---|
| ระยะขอบซ้าย-ขวาของการ์ด | 12 (`space3`) | **24** (`space6`) |
| แนวซ้ายของข้อความ/ปุ่ม/คนถูกใจ | 12 จากขอบจอ | **78** (= 24 + 40 avatar + 14 gap) |
| รูป | ชนขอบจอทั้งสองด้าน | อยู่ในคอลัมน์ขวา เริ่มที่ 78 **ล้นเฉพาะขอบขวา** |
| ระยะ avatar ↔ เนื้อหา | 10 | **14** (`gap-3.5` ตามไฟล์อ้างอิง) |

> **หมายเหตุเรื่อง 14px**: ไม่ใช่ค่าใน `WynSpacing` scale (มี 12 กับ 16 ไม่มี 14) — เป็นค่าที่ไฟล์
> อ้างอิงกำหนดไว้ตรง ๆ (`gap-3.5`) จัดเป็น micro-spacing exception ประเภทเดียวกับที่ DS-008 §2
> ตัดสินไว้แล้วว่ายอมรับได้เมื่อการบังคับเข้า 4px grid จะทำให้ภาพแย่ลง — ให้เพิ่ม comment กำกับในโค้ด
> ว่ามาจาก `01-home.tsx` ไม่ใช่ค่าที่คิดเอง

### รูปภาพ

**หลายรูป** — แถวการ์ดแนวนอน snap ทีละใบ (ของเดิม ไม่เปลี่ยนพฤติกรรม):
- ความกว้างการ์ด = **82% ของคอลัมน์เนื้อหาที่หัก right padding แล้ว** (288 บนจอ 390) → **236**
- ระยะห่างการ์ด **8** · สัดส่วน **4:5** · มุมโค้ง **16** — เหมือนเดิมทุกค่า
- รูปถัดไปโผล่ **68** บนจอ 390
- ไอคอนมุมขวาล่างของรูปแรก (บอกว่ามีหลายรูป) — คงไว้

> ค่า 82% เดิมในโค้ดคิดจาก**ความกว้างทั้งจอ** (การ์ด 320 โผล่ 62) ส่วนไฟล์อ้างอิงคิดจาก**คอลัมน์
> เนื้อหา** พอย้ายเข้าคอลัมน์แล้วเลข 82% เดิมจะให้การ์ด 236 โผล่ 68 เอง — **ไม่ต้องแก้ค่า
> `postCardWidthFraction` แค่เปลี่ยนฐานที่คูณ**

**รูปเดียว** — เต็มความกว้างคอลัมน์เนื้อหา (78 → 366), สัดส่วนจริงของรูปเหมือนเดิม (clamp 0.8–1.91,
สูงไม่เกิน 75% ของจอ ตาม `PostImageFrame`), **เพิ่มมุมโค้ง 16** เพราะตอนนี้ไม่ชนขอบจอแล้ว มุมเหลี่ยม
บนพื้นขาวจะดูเหมือนวาดไม่เสร็จ

## Interactions

ไม่เปลี่ยนแม้แต่จุดเดียว — `InkWell` ครอบทั้งการ์ด, `DoubleTapLike`, `_CardSnapPhysics`,
`_openMoreMenu`, `_openRedropSheet` ทำงานเหมือนเดิม

## States

ไม่มี state ใหม่ — สีทุกสถานะคงเดิมทั้งหมด (หัวใจแดงเมื่อถูกใจ / รีโพสต์ sapphire เมื่อรีโพสต์แล้ว /
ที่เหลือ graphite)

## Responsive Behavior

ทุกค่าเป็น px คงที่ ยกเว้นความกว้างการ์ดรูปที่เป็น % ของคอลัมน์ — ต้องทดสอบที่ **360** (จอแคบสุดที่
รองรับ) ว่าคอลัมน์เนื้อหาเหลือ 282 การ์ดรูป 212 แล้วชื่อ+เวลา+ปุ่ม ⋯ ยังอยู่บรรทัดเดียวไม่ล้น

## Accessibility

ไม่กระทบ — `Semantics` ทุกจุดคงเดิม, touch target ของแถวปุ่มยังคง 44px (มาจาก `ActionMetric`
ที่ไม่ต้องแก้), ต้องผ่าน textScale 130% เหมือนเดิม (คอลัมน์แคบลง 66px ทำให้ข้อความยาวขึ้นในแนวตั้ง
แต่ไม่ควรล้นแนวนอน)

## Design Rules

1. **ทุก section ในคอลัมน์เนื้อหาต้องเริ่มที่แนวเดียวกัน (78)** — ถ้าอนาคตเพิ่ม section ใหม่ในการ์ด
   ต้องอยู่ในคอลัมน์นี้ ห้ามวางชิดขอบจอ ยกเว้นรูปที่ตั้งใจให้ล้นขอบขวา
2. **ล้นได้เฉพาะขอบขวาเท่านั้น** ห้ามล้นขอบซ้าย (จะทำให้แนวคอลัมน์พัง ซึ่งเป็นทั้งหมดของงานนี้)
3. 6 จุดต่อไปนี้ในไฟล์อ้างอิง **ห้ามทำตาม** เพราะ Founder สั่งเปลี่ยนไปแล้วทีหลัง:
   | จุด | ไฟล์อ้างอิงเขียนไว้ | ต้องคงของจริง | ที่มา |
   |---|---|---|---|
   | สีหัวใจถูกใจ | sapphire | **แดง** | Founder 2026-09-01 "ใจอยากได้สีแดง" |
   | แถวปุ่ม | 4 ปุ่ม (มีไอคอนตา) | **3 ปุ่ม** | WYN-088 + ยืนยันซ้ำ 2026-09-03 |
   | แท็บ | 4 แท็บ (มี "ล่าสุด") | **3 แท็บ** | WYN-090 |
   | ไอคอนขวาบน | แว่นขยาย | **แชท** | WYN-031 |
   | ฟอนต์ | Fraunces + Inter | **ฟอนต์ระบบ** | Founder 2026-08-30 |
   | สีพื้น | ครีม `#FAF9F6` | **ขาว `#FFFFFF`** | WYN-105 |

## Handoff

ส่ง AI Coding:

1. เปลี่ยนโครง `Column` เป็น `Row(avatar, Expanded(Column))` ตามผังด้านบน — ย้าย `Padding` แนวนอน
   จากระดับ section ไปเป็น `right: 24` ต่อ section ภายในคอลัมน์ และ **เว้น right padding เฉพาะแถวรูป**
   — ทำทั้ง **`home_drop_card.dart`** และ **`home_pop_card.dart`** (การ์ด Pop มีคลิปแทนรูป และมีปุ่ม
   น้อยกว่า 1 ปุ่ม แต่โครงสองคอลัมน์เหมือนกันทุกประการ) · **ห้ามแตะไฟล์ Pop อื่น**
2. `HomeFeedImagePeekCarousel` / `PostImageCarousel`: เปลี่ยนฐานที่คูณ 82% จากความกว้างทั้งจอเป็น
   ความกว้างคอลัมน์เนื้อหาที่หัก 24 แล้ว (ค่า `postCardWidthFraction` เองไม่ต้องแก้)
3. `PostImageFrame` (รูปเดียว): เพิ่มมุมโค้ง 16 — ตรวจว่าไม่กระทบ Drop Detail ที่ใช้ widget เดียวกัน
   (ถ้ากระทบ ให้เพิ่มพารามิเตอร์ radius แทนการ hardcode)
4. อัปเดต widget test / golden ที่ผูกกับตำแหน่ง pixel ของการ์ด — คาดว่ามีหลายตัวที่ต้องแก้ค่าคาดหวัง
5. `flutter analyze` สะอาด + `flutter test` ผ่านครบ ไม่มี regression

## คำตอบ 2 ข้อที่ค้าง (Founder ตอบแล้ว 2026-09-03)

### 1. `HomePopCard` — **แก้ด้วย** ("ให้ทั้งฟีดหน้าตาเหมือนกัน")

Founder อนุมัติให้แตะ `home_pop_card.dart` เป็นข้อยกเว้นเฉพาะงานนี้ เหตุผลคือการ์ด Pop อยู่ในฟีด Home
เดียวกันและใช้โครง stack เหมือนกันเป๊ะ ถ้าแก้แค่ Drop ฟีดจะมีการ์ด 2 สไตล์ปนกันเห็นชัด

**ขอบเขตของข้อยกเว้นนี้**: เฉพาะ `home_pop_card.dart` (ไฟล์ของฟีด Home) เท่านั้น — ไฟล์ Pop อื่น
(`pop_clip_view.dart`, `pop_comment_sheet.dart`, `pop_single_clip_screen.dart`) **ยังอยู่ใต้กติกาเดิม
"ห้ามแก้ไฟล์ Pop โดยตรง"** ห้ามแตะ

การ์ด Pop มี 3 ปุ่ม (ถูกใจ/คอมเมนต์ — ไม่มีรีโพสต์เพราะ Pop ไม่มีคอนเซปต์ ReDrop) และมีคลิปแทนรูป
โครงสองคอลัมน์ใช้เหมือนกันทุกประการ

### 2. ทรงหัวใจ — **แบบ B (lucide)**

Founder เลือกทรงที่ไฟล์อ้างอิงใช้จริง — ต้นเหตุที่หัวใจในแอปดูไม่ตรงกับที่ออกแบบไว้คือ `01-home.tsx`
ใช้ไอคอนจาก `lucide-react` แต่ตอน implement ใช้ `Icons.favorite` ของ Material ซึ่งเป็นคนละทรง
(Material อ้วนกว่า ไหล่กว้างกว่า ปลายมนกว่า)

**แยกเป็นงานย่อย WYN-108** ไม่รวมในรอบนี้ เพราะเป็นคนละลักษณะงาน (สร้าง icon widget + ไล่เปลี่ยน
ทั้งแอป) และถ้ารวมกับการรื้อโครงการ์ดจะเป็น PR ใหญ่เกินไปจนรีวิวยาก — ดูรายละเอียดที่
