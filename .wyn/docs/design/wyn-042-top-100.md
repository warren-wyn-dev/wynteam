## ความสอดคล้องกับ DS-009 (Rainbow Accent — ล็อกไว้แค่ 2 จุดทั้งระบบ) — อ่านก่อนเริ่ม

DS-009 อนุญาต Rainbow แค่ 2 จุด: (1) Trending avatar ring ใน `TrendingTile` (2) active feed-mode indicator ใน Home — WYN-040 เคย reuse จุดที่ 1 ซ้ำใน Discovery's Trending Now ได้เพราะเป็น **widget เดียวกัน ความหมายเดียวกัน** ("นี่คือเนื้อหาที่กำลังนิยมในช่วง 48 ชม.ล่าสุด") ไม่ใช่การตีความใหม่

**Top 100 ต่างออกไป**: Product นิยาม Top 100 เป็นคนละ concept จาก "Trending Now" อย่างตั้งใจ (คนละ time window — 7 วัน vs 48 ชม., คนละหน้า, คนละจุดประสงค์ — "chart รายสัปดาห์" ไม่ใช่ "กำลังฮอตตอนนี้") ถ้าใส่ rainbow ring แบบเดียวกันลงในรายการ 100 แถวยาวๆ จะเกิด 2 ปัญหา: (ก) เป็นการตีความความหมาย "trending" ใหม่ให้ครอบคลุม Top 100 ด้วย ซึ่ง Product ไม่ได้ตั้งใจให้เป็นแนวคิดเดียวกัน (ข) การมี ring ซ้ำ 100 ครั้งในหน้าเดียวเปลี่ยนสัดส่วนพื้นที่ Rainbow บนหน้าจอไปมากกว่าที่ DS-009 อนุมัติไว้ (อนุมัติไว้สำหรับแถว/grid สั้นๆ ไม่ใช่ list ยาว 100 รายการ) — **สรุป: หน้า Top 100 ห้ามมี Rainbow ring เด็ดขาด** ถือเป็นการตัดสินใจของ Design รอบนี้ ไม่ใช่แค่ข้อสังเกต ถ้า Founder ต้องการ visual accent พิเศษสำหรับ Top 100 ในอนาคตให้เสนอเป็น design proposal ใหม่แยกต่างหาก

**การ implement**: เพิ่ม optional parameter ใหม่ให้ `TrendingTile` (WYN-017) — `showRainbowRing` (`bool`, default `true`) — Top 100 เรียกด้วย `showRainbowRing: false` เพื่อ reuse โครงสร้าง image/thumbnail/poll-placeholder/play-icon เดิมทั้งหมดโดยไม่ fork widget ใหม่ซ้ำ ส่วน caller เดิมทั้ง 2 จุด (Home's Trending row, Discovery's Trending Now) ไม่ต้องแก้ไขอะไรเลยเพราะ default ยังเป็น `true` เหมือนเดิม — เมื่อ `showRainbowRing: false` ให้ตัด `Container` ที่มี `gradient: WynColors.rainbowAccent` ออก เหลือแค่ภาพ/thumbnail ตรงๆ ไม่มีขอบ/padding พิเศษ

## Screen: `Top100Screen` (widget ใหม่ — full-screen, เปิดจาก Discovery)

Purpose: แสดง leaderboard เนื้อหา (Drop+Pop รวมกัน) 100 อันดับสูงสุดในรอบ 7 วันที่ผ่านมา ให้ความรู้สึก "chart ประจำสัปดาห์" ที่ชัดเจนกว่า Trending Now

User Flow: เปิด Discovery (หน้า Search, WYN-040) → เลื่อนถึง "Trending Now" section → แตะลิงก์ "ดู Top 100" ท้าย section → เปิด `Top100Screen` เต็มจอ → เลื่อนดูรายการเรียงอันดับ #1–100 → แตะรายการใดๆ → เปิด `DropDetailScreen`/`PopSingleClipScreen` ตามประเภท (เหมือนที่ Trending Now ทำ) → กด back กลับมาที่ Discovery เดิม

Components (บนลงล่าง):

### AppBar
- `Text('WYN Top 100')` เป็น title มาตรฐาน ไม่มีอะไรพิเศษ — ปุ่ม back เริ่มต้นของ Flutter

### Leaderboard list — `ListView.builder` แนวตั้งเดี่ยว (ไม่ใช่ grid)
เหตุผลที่เลือก list ไม่ใช่ grid (ต่างจาก Trending Now ที่เป็น grid 3 คอลัมน์): ตัวเลขอันดับต้องเด่นชัดเป็นจุดสนใจหลักของหน้านี้ (จุดประสงค์ทั้งหมดของ "Top 100" คือการเห็นอันดับ) — grid บีบพื้นที่ให้ตัวเลขอันดับเป็นแค่ badge เล็กๆ มุมภาพ อ่านยากกว่า list ที่ให้ตัวเลขเป็นองค์ประกอบเท่าเทียมกับภาพ (มิเรอร์ mental model ของ music/video chart ทั่วไปที่คุ้นเคย — ระวัง: **ไม่ได้ลอก layout เฉพาะของแพลตฟอร์มไหน** เป็นแค่ list layout พื้นฐานที่มีเลขนำหน้า ซึ่งเป็น pattern สากลไม่ผูกกับแบรนด์ใดเป็นการเฉพาะ ไม่ขัด DS-001 ข้อ "ห้ามลอก Layout IG/TikTok/Threads")

แต่ละแถว (`_Top100Row`):
- `Row` ประกอบด้วย 3 ส่วนแนวนอน:
  1. **เลขอันดับ**: `SizedBox(width: 40)` ครอบ `Text('#${index + 1}')` จัดกึ่งกลาง style `Theme.of(context).textTheme.titleLarge?.copyWith(fontWeight: FontWeight.bold)` — **ทุกอันดับใช้สไตล์เดียวกันหมด ไม่มีสีทอง/เงิน/ทองแดงพิเศษสำหรับ #1-3** (ไม่ประดิษฐ์ความหมายสีใหม่ที่ไม่มีใน DS-001 — ถ้า Founder ต้องการ emphasis พิเศษสำหรับ Top 3 ในอนาคตให้เป็นการตัดสินใจแยก)
  2. **Thumbnail**: `TrendingTile(item: item, onTap: ..., showRainbowRing: false)` ตรงๆ (ขนาด 94x94 เดิมของ widget ไม่ต้องปรับ — Design เลือกไม่เพิ่ม size-override parameter ใหม่ให้ `TrendingTile` เพื่อลด diff โดยไม่จำเป็น ยอมรับว่าแถวจะมีความสูงเท่าเดิมทั้ง 100 แถว)
  3. **ข้อมูลย่อ**: `Expanded` + `Column` แสดงชื่อผู้เขียน (`item.authorNameOrUsername`, `titleSmall`, 1 บรรทัด truncate) — **ไม่แสดง caption เต็ม/ตัวเลข engagement ดิบใดๆ** (ตาม Product's Requirement 4 — โชว์แค่อันดับ ไม่โชว์คะแนนจริง) เพื่อให้แถวกระชับ scan ง่ายเหมือน chart
- ทั้งแถว (นอกเหนือจาก thumbnail ที่มี tap ของตัวเองอยู่แล้วจาก `TrendingTile`) ไม่ต้องมี `InkWell` ครอบเพิ่ม — tap ของ `TrendingTile` เพียงพอ (แถวไม่มี action อื่นให้ทับซ้อน ต่างจาก Suggested Users ที่มีปุ่ม Follow ต้องแยก tap area)
- `Semantics(label: 'อันดับที่ ${index + 1}, ${item.authorNameOrUsername}, กดเพื่อดู${isPop ? "วิดีโอ" : "รูป"}', ...)` ครอบทั้งแถว — ให้ screen reader ประกาศอันดับก่อนชื่อเสมอ (ตรงตามลำดับความสำคัญของข้อมูลในหน้านี้)

### Loading/Empty/Error (ทั้งหน้าเดียว ไม่ใช่ fail-safe ต่อ section แบบ Discovery เพราะมีแค่ list เดียว)
- Loading: `CircularProgressIndicator` กึ่งกลางหน้า (มิเรอร์ pattern ของ `RecentlyDeletedDropsScreen`/`ProfileDraftsTab`)
- Error: ข้อความ error + ปุ่ม "ลองใหม่" (retry ยิง fetch ใหม่) — มิเรอร์ pattern เดียวกันเป๊ะ ("a fetch failure shows an error with a retry button")
- Empty: `Text('ยังไม่มีเนื้อหาติด Top 100 ตอนนี้')` กึ่งกลางหน้า

## Entry Point: ลิงก์ "ดู Top 100" ท้าย Discovery's "Trending Now" section

แก้ `DiscoveryView` (`app/lib/features/search/presentation/widgets/discovery_view.dart`, WYN-040) — เพิ่ม `TextButton` เล็กๆ ต่อท้าย `GridView` ของ `_buildTrendingNowSection` (ภายใน `FutureBuilder` เดียวกัน หลัง grid แต่ก่อน return ปิด — แสดงเฉพาะตอนที่ Trending Now มีข้อมูลแล้ว ไม่แสดงตอน loading/error/empty):

```dart
Align(
  alignment: Alignment.centerRight,
  child: TextButton(
    onPressed: () => Navigator.of(context).push(
      MaterialPageRoute(builder: (_) => Top100Screen(...)),
    ),
    child: const Text('ดู Top 100'),
  ),
),
```

- สไตล์ `TextButton` ปกติ (Cyan text ตาม theme default ของ `TextButton`) — ไม่ใช่การ์ด/ปุ่มใหญ่ ให้เป็นแค่ลิงก์เล็กๆ มุมขวา ไม่แย่ง visual weight จาก grid หลัก
- **ไม่เพิ่ม section ใหม่/header ใหม่ใน `DiscoveryView`** ตามที่ Product แนะนำ (Top 100 สมควรรู้สึกเป็นหน้าที่แยกออกมาต่างหาก ไม่ใช่แค่อีก horizontal list ปนกับ 5 section เดิม)

## Interactions
- แตะ thumbnail ใดๆ → เปิด `DropDetailScreen`/`PopSingleClipScreen` ตามประเภท (มิเรอร์ `_openDrop`/`_openPop` pattern ของ `DiscoveryView` เป๊ะ)
- ไม่มี pull-to-refresh (มิเรอร์ non-goal เดียวกับ Discovery/Hashtag Feed — bounded single fetch, ปิดแล้วเปิดใหม่คือวิธี refresh)
- ไม่มี "ดูเพิ่มเติม"/pagination เกิน 100 (ตามชื่อ feature เอง "Top 100" คือ bounded fixed-size list อยู่แล้วโดยธรรมชาติ)

## States
- Loading → Data (100 หรือน้อยกว่าถ้ามีเนื้อหาไม่ถึง) / Empty / Error+Retry

## Responsive Behavior
- `ListView.builder` มาตรฐาน ไม่มี breakpoint พิเศษ (list แนวตั้งธรรมดาไม่มีปัญหา responsive เหมือน grid)

## Accessibility
- ทุกแถวมี `Semantics(label: ..., button: true)` ระบุอันดับ+ชื่อผู้เขียนตามลำดับความสำคัญ (ดู Components ด้านบน)
- ลิงก์ "ดู Top 100" มี label ชัดเจนอยู่แล้วจากตัวหนังสือปุ่มเอง ไม่ต้องเพิ่ม Semantics แยก

## Design Rules
1. **ห้ามมี Rainbow ring ในหน้านี้เด็ดขาด** (ดูหัวข้อ DS-009 ด้านบน — กติกาที่สำคัญที่สุดของ task นี้)
2. **ห้ามใส่สี/badge พิเศษสำหรับอันดับ Top 3** — ทุกอันดับ style เดียวกัน (ดู Components)
3. **ห้ามแสดงตัวเลข engagement ดิบ/คะแนนจริงใดๆ** ในหน้านี้ (ตาม Product's Requirement 4) — แสดงได้แค่เลขอันดับเท่านั้น
4. Section header/ปุ่ม/สี ทั้งหมดใช้ style เดิมของระบบ ไม่ประดิษฐ์ typography/สีใหม่

## Non-goals รอบนี้
- **ไม่มี Top 100 Creator** (Product's Requirement 1 — Content เท่านั้นรอบนี้)
- **ไม่มี notification เมื่อเนื้อหาติด Top 100** (เป็นสโคปของ WYN-043, Phase 5)
- **ไม่มี filter/tab แยก Drop vs Pop** ภายใน Top 100 (รวมเป็น list เดียวมิเรอร์ Trending Now)
- **ไม่มี pull-to-refresh/pagination เกิน 100**

## Data Layer — สิ่งที่ต้องสร้างใหม่ (สำหรับ AI Coding)

**Flutter**:
- `HomeRepository` (WYN-007/017/018/041) เพิ่ม method ใหม่ `fetchTopContent({int limit = 100})` — มิเรอร์โครงสร้างของ `fetchTrending()` เป๊ะ (fetch จาก `home_feed`, ดึง liked/saved/redropped/poll-state/blocked-author-ids ผ่าน private helper เดิมทั้งหมด, map เป็น `HomeFeedItem`, `removeWhere` ตัดบัญชีที่ `authors_posting_blocked()` คืนมา, sort ด้วย `engagementScore()`, `.take(limit)`) — **ต่างจาก `fetchTrending()` แค่ 2 จุด**: (1) time window เป็นค่าคงที่ใหม่ `_topContentWindow = Duration(days: 7)` (ไม่ใช่ `_trendingWindow` เดิม) (2) candidate limit เป็นค่าคงที่ใหม่ `_topContentCandidateLimit = 500` (ไม่ใช่ `trendingCandidateLimit` เดิม) — **ห้ามแก้ `fetchTrending()`/`_trendingWindow`/`trendingCandidateLimit` เดิมแม้แต่บรรทัดเดียว** ตามที่ Product ระบุไว้ชัดเจน — ถ้าเห็นว่า body ของทั้งสอง method คล้ายกันมากจนอยากรวมเป็น private helper ร่วม (parameterize ด้วย window/candidateLimit) ให้ Coding ตัดสินใจเองว่าคุ้มกับความเสี่ยง regression ต่อ `fetchTrending()` ที่ผ่าน QA แล้วหรือไม่ — ถ้าไม่มั่นใจให้ copy โครงสร้างแยกไปเลยดีกว่า (smallest safe change มาก่อน DRY ในกรณีนี้)
- `TrendingTile` (`app/lib/features/home/presentation/widgets/trending_tile.dart`) เพิ่ม optional param `showRainbowRing` (`bool`, default `true`) — เมื่อ `false` ตัด `Container`/gradient ring ออก เหลือแค่ภาพ/thumbnail ตรงๆ ขนาดเท่าเดิม (90x90 หรือ 94x94 ตามที่ไม่มี ring ห่อ) — caller เดิม 2 จุด (`home_feed_screen.dart`, `discovery_view.dart`) ไม่ต้องแก้ไขเพราะ default คงพฤติกรรมเดิม
- `Top100Screen` ใหม่ (แนะนำ `app/lib/features/search/presentation/top_100_screen.dart` หรือตำแหน่งเทียบเท่าที่ Coding เห็นสมควร — ไม่ผูกกับ feature folder ใดเป็นพิเศษเพราะเป็นหน้าที่เข้าถึงจาก Discovery แต่เป็นแนวคิดอิสระ) รับ dependencies เดียวกับที่ `DiscoveryView` ใช้เพื่อ navigate (`homeRepository`/`dropRepository`/`popRepository`/`followRepository`/`profileRepository`/`savedRepository`) — FutureBuilder เดียวครอบทั้งหน้า เรียก `fetchTopContent()`
- แก้ `DiscoveryView`: เพิ่มลิงก์ "ดู Top 100" ตามที่ระบุใน Entry Point ด้านบน (ต้องมี `homeRepository` reference อยู่แล้วผ่าน `discoveryRepository`/ต้อง pass เข้า `DiscoveryView` เพิ่มถ้ายังไม่มี — Coding ตรวจสอบ constructor เดิมว่าต้องเพิ่ม param ใหม่หรือ reuse ของเดิมได้)

**Tests ที่ต้องมี**: widget test ของ `Top100Screen` (แสดงอันดับถูกต้อง #1 ถึง #N ตามลำดับผลลัพธ์, ไม่มี rainbow ring, ไม่โชว์ตัวเลข engagement ดิบ, tap แถวเปิดหน้าปลายทางถูกต้องตามประเภท, empty/error state), regression test ยืนยัน `TrendingTile`'s 2 caller เดิมยังมี ring เหมือนเดิม (default `true` ไม่กระทบ), unit test เชิงเอกสาร/comment ยืนยัน `fetchTopContent()` ใช้ window/candidate limit ต่างจาก `fetchTrending()` จริง (ถ้าเขียน integration test ไม่ได้เพราะไม่มี harness เหมือนที่ WYN-041 เจอ ให้บันทึกเหตุผลเดียวกันไว้)

## Handoff รวม

ส่งต่อ AI Coding (`/code`) เพื่อ implement Screen + Data Layer ข้างต้น — เน้นย้ำ 2 กติกาที่ห้ามพลาด: (1) ห้ามมี Rainbow ring ในหน้า Top 100 เด็ดขาด (2) ห้ามแตะ `fetchTrending()`/`_trendingWindow`/`trendingCandidateLimit` เดิม
