## ปัญหาที่งานนี้แก้

ตรวจโค้ดแล้วพบว่าตอนนี้ **รูปโดนครอป 2 รอบ โดยคนโพสต์คุมไม่ได้สักรอบ**:

1. **ตอนอัปโหลด** — `centerCropToSquare` (`app/lib/features/drop/data/square_crop.dart`) ครอปทุกรูป
   เป็นจัตุรัส 1:1 จากกึ่งกลางภาพ ไม่มี UI ให้เลือกหรือขยับ คอมเมนต์ในไฟล์เขียนไว้เองว่าเป็น
   "V0.1 round" ที่ตั้งใจทำแบบง่ายไว้ก่อน — เป็นงานค้าง ไม่ใช่ของเสีย
2. **ตอนแสดงในฟีด** — การ์ดรูปหลายใบเป็น 4:5 (`postCardAspectRatio`) จัตุรัสจึงโดนตัดบน-ล่างอีกที

ผลข้างเคียงที่ตามมา: **WYN-093 ("รูปยึดสัดส่วนจริง") ไม่เคยได้ทำงานจริงเลย** เพราะทุกรูปที่โพสต์ผ่าน
แอปเป็นจัตุรัสมาตั้งแต่ต้นทางอยู่แล้ว

## Screen

`CreateDropScreen` (`app/lib/features/drop/presentation/create_drop_screen.dart`) — และ
`square_crop.dart` ที่จะถูกแทนที่ด้วยตัวครอปที่รับสัดส่วนได้

## Purpose

ให้คนโพสต์เลือกสัดส่วนรูปได้เอง แทนที่จะโดนบังคับจัตุรัสแล้วโดนตัดซ้ำอีกรอบตอนแสดงผล

## User Flow

```
เลือกรูป (สูงสุด 9 รูป — ไม่เปลี่ยน)
  ↓
เห็นรูปพร้อมแถบชิปเลือกสัดส่วน  ← ใหม่
  ↓
เลือกสัดส่วน → ใช้กับทุกรูปในโพสต์นั้นพร้อมกัน
  ↓
เขียนแคปชัน → แชร์
```

## Components

### แถบชิปเลือกสัดส่วน (ใหม่)

วางใต้รูปพรีวิวในหน้าสร้างโพสต์ — ชิปทรงเดียวกับที่แอปใช้อยู่แล้ว (ขอบ `hairline`, ตัวอักษร
`graphite`; ตอนเลือกเป็นขอบ+ตัวอักษร `sapphire` พื้น `#F4F7FB`)

| ชิป | สัดส่วน | หมายเหตุ |
|---|---|---|
| ต้นฉบับ | สัดส่วนจริงของรูป | ฟีดรองรับอยู่แล้ว (บีบในช่วง 0.8–1.91 ตาม WYN-093) — ตัวเลือกนี้ทำให้ WYN-093 ได้ใช้จริงครั้งแรก |
| 1:1 | จัตุรัส | พฤติกรรมเดิมทุกประการ |
| **4:5** | แนวตั้ง | **ค่าเริ่มต้น** — Founder ระบุเอง |
| 16:9 | แนวนอน | อยู่ในช่วงที่ฟีดรองรับ (1.78 < 1.91) |

### กติกาที่ Founder ตัดสินแล้ว

> **"อัตราส่วน 4:5 เท่ากัน"** (2026-09-04)

- **หนึ่งโพสต์ = หนึ่งสัดส่วน** — เลือกครั้งเดียวใช้กับทุกรูปในโพสต์นั้น ไม่ใช่เลือกแยกทีละรูป
  (เหตุผลเชิงออกแบบที่เสนอไว้และ Founder เลือก: แถวการ์ดในฟีดจะขอบบน-ล่างตรงกันทุกใบ และกติกา
  "การ์ดกว้าง 82% ของคอลัมน์" ที่เพิ่งทำใน WYN-107 ยังใช้ได้ตรงไปตรงมา)
- **ค่าเริ่มต้นคือ 4:5** — ตรงกับสัดส่วนการ์ดในฟีดพอดี จึงไม่โดนครอปรอบที่ 2 อีก คนโพสต์เห็นตอนโพสต์
  ยังไง ในฟีดออกมาแบบนั้นเป๊ะ

## Interactions

- แตะชิป → รูปพรีวิวทุกใบเปลี่ยนสัดส่วนทันที (ครอปตอนกด "แชร์" ไม่ใช่ตอนแตะชิป — จะได้เปลี่ยนไปมาได้
  โดยไม่เสียคุณภาพจากการครอปซ้อนครอป)
- เพิ่มรูปใหม่ทีหลัง → ใช้สัดส่วนที่เลือกไว้แล้วของโพสต์นั้นอัตโนมัติ

## States

- **ค่าเริ่มต้น**: 4:5 เลือกไว้ให้เลย
- **ระหว่างครอปตอนกดแชร์**: ใช้ `_isCropping` เดิมที่มีอยู่แล้ว (ปุ่มแชร์กดซ้ำไม่ได้)
- **ไม่มีรูป** (โพสต์ข้อความล้วน): ไม่แสดงแถบชิปเลย

## Responsive Behavior

แถบชิปเลื่อนแนวนอนได้ถ้าจอแคบ (`SingleChildScrollView`) — pattern เดียวกับแท็บฟีดในหน้า Home

## Accessibility

- ชิปแต่ละอันเป็นปุ่มจริง มี `Semantics(label:, button: true, selected:)` — ประกาศสถานะเลือก/ไม่เลือก
  ด้วยข้อความ ไม่ใช่ด้วยสีอย่างเดียว (กติกา DS-001 ข้อ 5)
- touch target ≥44×44 ตามปกติ

## Design Rules

1. **หนึ่งโพสต์ใช้สัดส่วนเดียว** — ห้ามให้แต่ละรูปในโพสต์เดียวกันมีสัดส่วนต่างกัน
2. ห้ามเพิ่มสัดส่วนนอกเหนือจาก 4 แบบข้างต้นโดยไม่ถาม Founder — และทุกแบบต้องอยู่ในช่วงที่ฟีดรองรับ
   (0.8–1.91) ไม่งั้นฟีดจะบีบให้อยู่ในช่วงแล้วครอปซ้ำอีก ซึ่งเป็นปัญหาเดิมที่งานนี้แก้

## ผลกระทบต่อฟีด (สำคัญ — ต้องแก้คู่กัน)

ตอนนี้ `postCardAspectRatio` เป็นค่าคงที่ `4/5` ทั้งระบบ (`app/lib/core/widgets/post_media.dart`)
พอโพสต์เลือกสัดส่วนได้แล้ว **การ์ดรูปในฟีดต้องวาดตามสัดส่วนของโพสต์นั้น ไม่ใช่ 4:5 ตายตัว**
มิฉะนั้นคนที่เลือก 16:9 จะยังโดนครอปเป็น 4:5 อยู่ดี — ซึ่งแปลว่างานนี้ไม่ได้แก้อะไรเลยสำหรับเขา

ต้องเก็บสัดส่วนที่เลือกไว้ในฐานข้อมูลระดับโพสต์ (คอลัมน์ใหม่ เช่น `drops.image_aspect_ratio`) แล้วส่ง
ต่อเข้า `PostImageCarousel`/`PostImageFrame` — **เป็นการเปลี่ยนโครงสร้างฐานข้อมูล จึงต้องขออนุมัติ
Founder ก่อนตามกติกา RULES.md**

## การครอป — Founder ตัดสินแล้ว: **ลากเลือกจุดครอปได้**

> "ลากเลือกจุดครอปได้ อนุมัติเพิ่มคอลัมน์" (2026-09-04)

ผู้ใช้ลากรูปในกรอบสัดส่วนที่เลือกไว้ เพื่อเลือกส่วนที่จะเก็บ — ไม่ใช่ตัดกึ่งกลางให้อัตโนมัติอีกต่อไป
สิ่งที่เห็นในกรอบตอนโพสต์คือสิ่งที่ออกมาในฟีดเป๊ะ

**ห้ามเขียนหน้าครอปใหม่** — แอปมีอยู่แล้วที่ `app/lib/features/profile/presentation/profile_photo_crop_screen.dart`
(WYN-104, ผ่าน QA แล้ว มีเทสของตัวเอง) รองรับลาก + ซูมด้วยสไลเดอร์ + ปุ่ม ยกเลิก/เสร็จสิ้น
งานคือ**ทำให้มันรับสัดส่วนเป็นพารามิเตอร์ได้** (ตอนนี้ล็อกจัตุรัสสำหรับ avatar) แล้วเรียกใช้จากหน้าสร้างโพสต์
— ห้ามแตะพฤติกรรมเดิมของ flow รูปโปรไฟล์ (ค่า default ต้องเป็นจัตุรัสเหมือนเดิมเป๊ะ)

4. **WYN-109d — ฟีด**: `PostImageCarousel`/`PostImageFrame` วาดตามสัดส่วนของโพสต์แทน
