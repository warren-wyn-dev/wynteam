# ZOKY-FULFILL-001: รับเองที่ร้าน + ร้านจัดส่งเอง (PRD draft)

Status: **DRAFT รอ Founder อนุมัติ**. ยังไม่ได้อนุมัติให้ implement, migrate หรือ deploy
Date: 2026-10-26
Source: Founder "Zoky จะมีให้เลือกจัดส่ง 2 แบบ คือ รับเองที่ร้าน → ระบุเวลาได้ ภายในเวลาปิดร้าน, ร้านจัดส่งเอง → ร้านต้องเป็นคนจัดส่งเอง"

## Founder decisions (2026-10-26)

| เรื่อง | คำตอบ |
|---|---|
| รับเองที่ร้าน: จ่ายเงินตอนไหน | จ่ายออนไลน์ตอนสั่ง |
| รับเองที่ร้าน: เลือกเวลาได้ไหม | เลือกเวลาได้เฉพาะ**วันนี้** ภายในเวลาปิดร้าน ไม่มีสั่งข้ามวัน |
| ร้านส่งเอง: เก็บเงินปลายทาง | **ร้านเลือกเปิดเองได้** เพราะเงินลูกค้าเข้าร้านโดยตรง |
| ร้านส่งเอง: เลือกเวลาส่ง | เลือกไม่ได้ ร้านต้องส่งเร็วที่สุด |

คำตัดสินนี้**แทนที่** DECISION 2026-10-10 "WYNOS Food is delivery only (no pickup, no scheduled orders)" เฉพาะส่วนรับเองที่ร้านและการเลือกเวลารับภายในวันนี้ ส่วนการจัดส่งยังห้ามสั่งล่วงหน้าเหมือนเดิม

## 1. สถานะปัจจุบัน (ตรวจโค้ด 2026-10-26)

- **ร้านจัดส่งเองมีอยู่แล้ว:**
  - ร้านกดสถานะ `pending_acceptance → preparing → ready_for_delivery → out_for_delivery → delivered` ใน Merchant app และแนบรูปตอนส่งถึง
  - ร้านตั้งรัศมีส่ง ระยะฐาน และค่าส่งต่อ กม. ได้ (`delivery_radius_km`, `delivery_base_km`, `delivery_fee_per_km`)
  - ระบบไม่มีไรเดอร์ของแพลตฟอร์ม
- **การจ่ายเงิน:** ลูกค้าจ่ายเข้าร้านโดยตรงผ่าน PromptPay, บัญชีธนาคาร หรือ QR ร้าน (ตรวจสลิป) และ Stripe ถ้าร้านเปิด **ยังไม่มีเงินปลายทาง**
- **ไม่มีประเภทออเดอร์ "รับเองที่ร้าน" ในฐานข้อมูล:**
  - มี `scheduled_for` และ RPC `food_create_scheduled_order_v*` จากระบบสั่งล่วงหน้าเดิม แต่ UI ปิดไว้ตั้งแต่ 2026-10-10
  - ร้านมีจุดรับอาหารแยกจากหน้าร้านแล้ว (`pickup_latitude/longitude/note`)
- **พื้นที่ให้บริการ:** server ตรวจว่าร้านและหมุดส่งอยู่ในจังหวัดมหาสารคาม (WYN-211)

## 2. Requirements

### P0 ทั้งสองแบบ
1. ออเดอร์มีประเภท `fulfillment_type`: `delivery` (ร้านส่งเอง) หรือ `pickup` (รับเองที่ร้าน) โดย **server เป็นคนกำหนดและตรวจ** ไม่เชื่อค่าจากเครื่องลูกค้า
2. ร้านเปิดหรือปิดแต่ละแบบได้เองใน Merchant app และต้องเปิดอย่างน้อย 1 แบบ ร้านที่มีอยู่เดิมให้ค่าเริ่มต้นเป็น `delivery` เปิด และ `pickup` ปิด
3. ลูกค้าเห็นป้าย "ร้านส่งเอง" หรือ "รับเองได้" ที่หน้ารายการร้านและหน้าร้าน และเลือกแบบได้ในหน้าตะกร้า
4. Merchant app, Zoky Admin และอีเมลหรือแจ้งเตือนแสดงประเภทออเดอร์ชัดเจน และรายงานยอดแยกตามประเภท

### P0 รับเองที่ร้าน
5. ลูกค้าเลือกเวลารับ**ของวันนี้**เป็นช่วงละ 15 นาที
   - เร็วสุด = ตอนนี้ + เวลาเตรียมของร้าน ร้านตั้งเองได้ ค่าเริ่มต้น 15 นาที
   - ช้าสุด = เวลาปิดร้านวันนี้ − เวลาเตรียม
   - **server ตรวจเวลาซ้ำ** ถ้าเลยเวลาปิด ร้านปิด หรือเวลาย้อนหลัง ให้ปฏิเสธออเดอร์
6. ไม่มีค่าส่ง ไม่ต้องปักหมุดที่อยู่ ไม่ต้องตรวจพื้นที่ของลูกค้า แต่ร้านยังต้องอยู่ในมหาสารคาม
7. **จ่ายออนไลน์เท่านั้น** ไม่มีเก็บเงินที่ร้าน
8. สถานะ: `pending_acceptance → preparing → ready_for_pickup → picked_up` และยกเลิกได้
9. ลูกค้าได้**รหัสรับอาหาร**สั้นๆ เช่น `A23` แสดงในหน้าออเดอร์ และร้านเห็นรหัสเดียวกัน
10. หน้าออเดอร์ของลูกค้ามีที่อยู่ร้าน จุดรับอาหาร และปุ่มนำทาง
11. แจ้งเตือนลูกค้าเมื่อร้านรับออเดอร์ และเมื่อร้านกด "พร้อมรับ"
12. **มาช้าหรือไม่มารับ:** (Founder 2026-10-26)
    - ลูกค้ามาช้ากว่าเวลานัดได้ ระบบไม่ตัดออเดอร์อัตโนมัติ
    - ถ้าลูกค้าไม่มารับหรือขอยกเลิก **ร้านเป็นคนตัดสินว่าจะคืนเงินหรือไม่** ระบบไม่คืนเงินเอง

### P0 ร้านส่งเอง
13. ใช้ flow เดิมทั้งหมด ส่งเร็วที่สุดเท่านั้น
14. **เก็บเงินปลายทาง (COD):**
    - ร้านเปิดเองได้ ค่าเริ่มต้นปิด และใช้ได้เฉพาะออเดอร์ `delivery`
    - ลูกค้าเลือก "จ่ายเงินสดตอนรับของ" ในหน้าตะกร้าได้เมื่อร้านเปิดไว้
    - ร้านกด "ได้รับเงินแล้ว" ตอนส่งถึง
    - server ห้าม COD ในออเดอร์ `pickup` และห้ามใช้เมื่อร้านไม่ได้เปิด
15. ร้านกดเปิดหมุดลูกค้าใน Google Maps หรือ Apple Maps เพื่อนำทางได้

### P1
- หน้าปักหมุดแสดงความแม่นยำ ±เมตร และเตือนเมื่อเกิน 60 เมตร (ใช้ `freshMapsGpsLocation` แบบเดียวกับ WYNOS Maps) สำคัญเพราะร้านขับไปส่งเอง
- จำกัดจำนวนออเดอร์รับเองต่อช่วงเวลา
- ยอดขั้นต่ำ หรือส่งฟรีเมื่อซื้อถึงที่กำหนด สำหรับร้านส่งเอง

### Out of scope
- ไรเดอร์ของแพลตฟอร์ม และการจัดส่งโดยบุคคลที่สาม
- สั่งล่วงหน้าข้ามวัน และเลือกเวลาส่งสำหรับ delivery
- เก็บเงินที่ร้านสำหรับ pickup

## 3. Acceptance criteria
- ร้านที่ปิด pickup: ส่ง `fulfillment_type=pickup` ผ่าน API ตรงแล้วถูกปฏิเสธ
- เวลารับก่อน (ตอนนี้ + เวลาเตรียม) หรือหลัง (ปิดร้าน − เวลาเตรียม) ถูกปฏิเสธ รวมถึงกรณีตั้งเวลาเครื่องผิด
- ออเดอร์ pickup ไม่มีค่าส่ง และไม่ต้องใช้หมุดลูกค้า
- COD: ร้านปิด COD หรือออเดอร์เป็น pickup → ถูกปฏิเสธ ร้านเปิด COD + delivery → สร้างออเดอร์ได้ สถานะชำระเงินเป็น "เก็บปลายทาง" จนร้านกดรับเงิน
- ลูกค้าคนอื่นดูรหัสรับอาหารของออเดอร์ที่ไม่ใช่ของตัวเองไม่ได้ (RLS)
- ร้านเปลี่ยนสถานะได้เฉพาะออเดอร์ของร้านตัวเอง และเปลี่ยนได้ตามลำดับที่ถูกต้องเท่านั้น
- ร้านเดิมทุกร้านทำงานเหมือนเดิมหลัง migration โดยทุกร้านเป็น delivery
- ไม่มีผลกับคูปอง ส่วนลด GP และระบบยกเลิกเมื่อไม่ชำระใน 10 นาที (ต้องผ่าน regression)

## 4. ต้องอนุมัติ (Change Control)
1. **Major product scope change:** เพิ่ม pickup และ COD แทนที่ decision 2026-10-10
2. **Database migration (additive):**
   - `food_orders`: เพิ่ม `fulfillment_type`, `pickup_at`, `pickup_code`, `payment_method='cod'`
   - store settings: เพิ่ม `pickup_enabled`, `delivery_enabled`, `cod_enabled`, `prep_minutes`
   - เพิ่มสถานะ `ready_for_pickup` และ `picked_up`
   - แก้ RPC สร้าง/quote ออเดอร์ และ RPC เปลี่ยนสถานะของร้าน
3. **Release:** Food + Merchant + Zoky Admin ผ่าน staging และ Founder gate

## 5. คำถามที่ยังเปิดอยู่
- ยกเลิก pickup หลังร้านรับออเดอร์แล้ว: ลูกค้ายกเลิกเองได้ไหม (ค่าที่เสนอ: ไม่ได้ ให้ติดต่อร้าน)
- COD มีผลกับการคิด GP อย่างไร
