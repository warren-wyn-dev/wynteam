# Product Full Spec — WYN-104

Status: full spec complete (2026-09-02) — ready for AI Design
แหล่งที่มา: `Wynos V1.0.0 Beta2.pdf` ข้อ 18/28, `.wyn/tasks/backlog/WYN-104.md`

Feature: หน้า Crop รูปโปรไฟล์ (pinch-to-zoom + drag) ก่อนบันทึกจริง

Goal: ให้ผู้ใช้ปรับตำแหน่ง/ซูมรูปโปรไฟล์เองก่อนบันทึกจริง แทนที่จะปล่อยให้ระบบ auto-crop/แสดงเป็นวงกลมเฉยๆ โดยไม่ให้ผู้ใช้ปรับ

Target User: ผู้ใช้ WYN Social ทุกคนที่เปลี่ยนรูปโปรไฟล์

## Problem — สถานะปัจจุบันจริง (ตรวจโค้ดแล้ว): ไม่มีการ crop จริงเลย เป็นงานใหม่ทั้งหมด

`EditProfileScreen._pickImage()` (บรรทัด 127-148) เลือกรูปผ่าน `ImagePicker` (resize 1024×1024, quality 85) แล้ว**เก็บ bytes ทั้งรูปสี่เหลี่ยมไว้ตรงๆ ไม่มีขั้นตอน crop ใดๆ เลย** — ที่ preview เห็นเป็นวงกลมบนหน้าจอ (`CircleAvatar`) เป็นแค่ **การ clip ทางภาพ (visual clip)** ของ widget เท่านั้น ไม่ใช่การ crop ไฟล์จริง — รูปที่ถูกอัปโหลดจริงคือรูปสี่เหลี่ยมเต็มตามที่เลือกมา (resize ให้พอดี 1024×1024 เท่านั้น ไม่ตัดขอบ) ผู้ใช้ไม่มีทางเลือกตำแหน่ง/ซูมเองเลยในระบบปัจจุบัน — ยืนยันว่านี่คืองานใหม่จริงตามที่ backlog ระบุไว้ ไม่มีอะไรให้ scope-correct

## Data Model Impact
**ไม่มี** — ไม่แก้ schema (`profiles.avatar_url`/`clubs.cover_url` เก็บ URL เดิม เปลี่ยนแค่ไฟล์ที่ถูกอัปโหลดให้เป็นรูปที่ crop แล้วแทนรูปดิบ)

## Requirements (UI/UX)

**1. Flow ใหม่**: เลือกรูป (camera/gallery, ใช้ picker เดิม) → **เปิดหน้า Crop ทันที** (หน้าจอใหม่ ไม่ใช่ bottom sheet) → ผู้ใช้ปรับซูม/ตำแหน่งในกรอบวงกลม → กด "เสร็จสิ้น" → crop จริงตามตำแหน่ง/ซูมที่ปรับ → กลับมาที่ `EditProfileScreen` พร้อมรูปที่ crop แล้วเป็น preview → กด "บันทึก" ตามปกติค่อยอัปโหลดจริง (ไม่เปลี่ยน timing การอัปโหลดจริง ยังคงอัปโหลดตอนกด "บันทึก" เหมือนเดิมตาม comment เดิมของไฟล์ "ไม่ upload ยัง แค่ preview จนกว่าจะกด บันทึก")

**2. หน้า Crop**:
- พื้นหลังเข้ม (สีเข้มกว่าปกติของแอป เพื่อให้กรอบวงกลม preview เด่น — ยืมแนวคิดเดียวกับ image cropper ทั่วไป เช่น IG/FB)
- วงกลม preview อยู่กึ่งกลางจอ ขนาดคงที่ (ไม่ปรับตามรูป)
- รองรับ **pinch-to-zoom** (2 นิ้ว) และ **drag** (1 นิ้ว) ขยับตำแหน่งรูปภายในกรอบ — ซูมได้ตั้งแต่ 1.0x (fit วงกลมพอดี ไม่ให้ซูมออกจนเห็นขอบว่าง) ถึงอย่างน้อย 3.0x
- AppBar: ปุ่ม "ยกเลิก" (ซ้าย, กลับไป `EditProfileScreen` โดยไม่เปลี่ยนรูปเดิม) + หัวข้อ "ปรับตำแหน่งรูป" + ปุ่ม "เสร็จสิ้น" (ขวา, ยืนยัน crop)

**3. Crop จริงหลังกด "เสร็จสิ้น"**: คำนวณ crop rectangle จริงจากตำแหน่ง/ซูมที่ผู้ใช้ปรับ ตัดรูปเป็นสี่เหลี่ยมจัตุรัส (จะถูกแสดงเป็นวงกลมในแอปอยู่ดี แต่ไฟล์ที่เก็บเป็นสี่เหลี่ยมจัตุรัสเหมือนมาตรฐานทั่วไป ไม่ใช่วงกลมจริงมี alpha — ป้องกันปัญหาพื้นหลังโปร่งใสไม่รองรับทุกที่ที่ใช้รูปนี้ เช่น การ์ดโพสต์ที่อาจโชว์อวตารเป็นสี่เหลี่ยมมนแทนวงกลมในบาง component)

## Data Flow / Package Choice

**Package ที่แนะนำ**: `crop_your_image` (pure-Dart, ไม่พึ่ง native platform channel) แทน `image_cropper` (ปลั๊กอิน native ที่มีข้อจำกัดบน Web ที่ทราบแล้ว — เสี่ยงเรื่อง WYN-104's Risk R1 เดิมที่ backlog ระบุไว้แล้วว่า "package อาจมีข้อจำกัดเรื่อง platform") — โปรเจกต์นี้ target ทั้ง Web/iOS/Android (`app/web`, `app/ios`, `app/android` ยืนยันจาก pubspec) และ pattern เดิมของโค้ดเบสทั้งหมดเลี่ยง native image plugin นอกจาก `image_picker` มาตลอด (ทุกจุดจัดการ bytes เองด้วย Dart ล้วน) — `crop_your_image` สอดคล้องกับ pattern นี้มากกว่า **ต้องให้ AI Design/Coding ยืนยันอีกครั้งก่อนติดตั้งจริงว่า maintain ดีและรองรับ Flutter SDK เวอร์ชันปัจจุบันของโปรเจกต์**

**Reuse**: cover picker ของ `CreateClubScreen`/`EditClubInfoScreen` (crop 16:9 ไม่ใช่วงกลม) **ไม่รวมอยู่ในสโคปนี้** — Founder ระบุเฉพาะ "รูปโปรไฟล์" (avatar) เท่านั้น ไม่ใช่รูปปก Club (ดู Out of Scope)

## Edge Cases

1. **ผู้ใช้กด "ยกเลิก" กลางหน้า Crop**: กลับไป `EditProfileScreen` โดยรูปโปรไฟล์เดิม (ที่ยังไม่ได้เปลี่ยน) ไม่เปลี่ยนแปลง — เหมือนไม่เคยกดเลือกรูปใหม่เลย
2. **รูปที่เลือกมาเป็นแนวนอน/แนวตั้งสุดขั้ว (เช่น panorama)**: บังคับ min zoom ให้ด้านที่สั้นกว่าเต็มพอดีกรอบวงกลมเสมอ (ไม่มีขอบว่าง/แถบสีดำในกรอบ)
3. **หมุนรูป (EXIF orientation จากกล้องมือถือ)**: ต้องอ่าน/แก้ EXIF orientation ก่อนเข้าสู่หน้า Crop (ปัญหาคลาสสิกของการ crop รูปจากกล้อง — รูปอาจดูหมุนผิดทิศถ้าไม่จัดการ) — ตรวจสอบว่า `image_picker`/package ที่เลือกจัดการให้อัตโนมัติหรือไม่ ถ้าไม่ต้องแก้เองก่อนส่งเข้าตัว cropper
4. **เครือข่ายช้า/ผู้ใช้ปิดแอประหว่าง crop**: ไม่มีผลกระทบ เพราะยังไม่อัปโหลดจนกว่าจะกด "บันทึก" ในหน้า `EditProfileScreen` (เหมือนเดิม)
5. **Accessibility**: ผู้ใช้ที่ใช้ screen reader ปรับ pinch/drag ไม่ได้ — ต้องมีปุ่ม +/- ซูมสำรอง (ไม่ใช่พึ่ง gesture อย่างเดียว) เพื่อให้ยังใช้งานได้ในระดับหนึ่ง (ระบุเป็น requirement เพิ่มเติมที่ AI Design ควรพิจารณา)

## Acceptance Criteria
- [ ] เลือกรูปโปรไฟล์ใหม่ (camera/gallery) → เข้าหน้า Crop ทันที (ไม่ผ่าน `EditProfileScreen` ก่อน)
- [ ] ซูม/ลากรูปในวงกลมได้ลื่นไหลทั้ง pinch และ drag
- [ ] กด "เสร็จสิ้น" → รูปที่ crop ตรงกับตำแหน่ง/ซูมที่ปรับจริง กลับไปแสดง preview ที่ `EditProfileScreen`
- [ ] กด "ยกเลิก" → รูปโปรไฟล์เดิมไม่เปลี่ยนแปลง
- [ ] กด "บันทึก" ที่ `EditProfileScreen` → อัปโหลดรูปที่ crop แล้ว (ไม่ใช่รูปดิบก่อน crop) ขึ้น storage จริง
- [ ] EXIF orientation จากกล้องมือถือแสดงถูกทิศทางในหน้า Crop (ไม่หมุนผิด)
- [ ] ทดสอบได้ทั้ง 3 platform (iOS/Android/Web)

## Dependencies
ไม่มี

## Out of Scope (รอบนี้)
- Crop รูปปก Club (`CreateClubScreen`/`EditClubInfoScreen`'s cover picker) — Founder ระบุเฉพาะรูปโปรไฟล์เท่านั้น
- Filter/effect รูป (ปรับความสว่าง/contrast ฯลฯ) — ไม่ถูกร้องขอ
- Crop รูปโพสต์ (Drop/Club post images) — ไม่ถูกร้องขอ ต่างบริบทกัน (โพสต์แสดงเป็นสี่เหลี่ยม ไม่ใช่วงกลม)
- บันทึกตำแหน่ง crop ไว้แก้ไขซ้ำภายหลัง (crop คือ one-way operation ต่อการอัปโหลดครั้งนั้น เหมือนมาตรฐานทั่วไป)

## Risks

| # | ความเสี่ยง | ระดับ | การป้องกัน |
|---|---|---|---|
| R1 | Flutter package สำหรับ pinch/drag crop อาจมีข้อจำกัดเรื่อง platform (iOS/Android/Web) | ต่ำ-กลาง | เลือก `crop_your_image` (pure-Dart) แทน native plugin ตามที่วิเคราะห์ไว้ข้างบน — ทดสอบทั้ง 3 platform ก่อนสรุป |
| R2 | EXIF orientation handling พลาดจนรูปหมุนผิดทิศเฉพาะบางอุปกรณ์ (พบบ่อยกับ iOS) | กลาง | ทดสอบด้วยรูปจากกล้องจริงหลายรุ่นอุปกรณ์ ไม่ใช่แค่รูปจาก gallery/simulator |

## Recommendation
อนุมัติ — งานนี้เป็นฟีเจอร์ใหม่จริง ไม่มี scope ที่ทำไปแล้วให้ correct เหมือนงานอื่นในกลุ่มนี้ ขนาดกลาง เสี่ยงต่ำ-กลางเรื่อง platform/EXIF เท่านั้น

## Handoff
ส่งต่อ **AI Design** (`/design`) — ต้องออกแบบหน้า Crop ใหม่ทั้งหน้า (พื้นหลังเข้ม, กรอบวงกลม, ปุ่ม +/- ซูมสำรองสำหรับ accessibility) ให้เข้ากับ Design System เดิมของ WYN (Sapphire accent, ไม่ใช้ Liquid Glass) → AI Coding (ยืนยัน package จริงก่อนติดตั้ง ตาม Data Flow section) → AI QA (เน้นทดสอบ EXIF orientation จากอุปกรณ์จริงหลายรุ่น + 3 platform)
