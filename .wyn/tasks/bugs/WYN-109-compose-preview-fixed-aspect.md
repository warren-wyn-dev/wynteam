## Bug

ในหน้าสร้างโพสต์ กดชิปเปลี่ยนสัดส่วนแล้ว **รูปพรีวิวไม่เปลี่ยนรูปทรงเลย** ยังเป็นกรอบ 4:5 ตายตัวทุกกรณี
byte ข้างในถูก re-cut จริงตามชิป แต่กรอบพรีวิวเป็น `SizedBox(width: 128, height: 160)` (= 4:5) คงที่
บวกกับ `Image.memory(fit: BoxFit.cover)` จึงครอปกลับเป็น 4:5 ให้ดูอยู่ดี

คนโพสต์จึงมองไม่เห็นสิ่งที่ตัวเองจะได้ ซึ่งเป็นหัวใจทั้งหมดของฟีเจอร์นี้

## ผิด spec 2 ข้อพร้อมกัน

- Interactions: "แตะชิป → **รูปพรีวิวทุกใบเปลี่ยนสัดส่วนทันที**"
- States/Purpose: "คนโพสต์เห็นตอนโพสต์ยังไง ในฟีดออกมาแบบนั้นเป๊ะ"

## Reproduction

1. หน้าสร้างโพสต์ → เลือกรูปแนวนอน 1 รูป
2. กดชิป `16:9` → รูปพรีวิวไม่เปลี่ยนรูปทรง (ยังเป็นสี่เหลี่ยมตั้ง 4:5)
3. กดชิป `1:1` → ก็ยังเป็น 4:5
4. กดชิป `ต้นฉบับ` → ก็ยังเป็น 4:5

## Expected

กรอบพรีวิวเปลี่ยนตาม `_aspectRatio` ทันที และแสดง byte ที่ re-cut แล้วแบบไม่ครอปซ้ำ

## Actual

กรอบคงที่ 128×160 · `BoxFit.cover` ครอปทับ → เห็น 4:5 เสมอ

## Fix ที่เสนอ

1. คำนวณความกว้าง/สูงของกรอบพรีวิวจาก `_aspectRatio.ratio` โดยยึดด้านสูง 160 ไว้เท่าเดิม
   (เช่น 16:9 → 284×160 · 1:1 → 160×160 · 4:5 → 128×160 เท่าเดิม)
2. สำหรับ `ต้นฉบับ` ที่ไม่มีสัดส่วนเดียว: ใช้สัดส่วนจริงของรูปแต่ละใบ (decode dimensions)
   หรือถ้าไม่คุ้มค่าใช้จ่าย ให้ใช้ `BoxFit.contain` บนกรอบเดิมเพื่อไม่ให้ครอปเพิ่ม — **แต่ต้องไม่ทำให้ผู้ใช้เข้าใจผิด**
3. ระวังไม่ให้ `ListView` แนวนอนล้น: กรอบ 16:9 กว้างขึ้นมาก ต้องทดสอบที่ 320/360px และที่ 9 รูป

## Regression Risk

ปานกลาง — แตะ layout ของ `ListView` แนวนอนในหน้าสร้างโพสต์
ต้องทดสอบ: 1–9 รูป × 4 สัดส่วน × ความกว้างจอ 320/360/390/430 × textScale 1.0/1.3

## Minor ที่ควรจัดการพร้อมกัน (ไม่ block)

- **M-109-1** — ชิปที่ถูกเลือกไม่มีพื้นหลัง `#F4F7FB` ตามที่ spec Components กำหนด (มีแค่ขอบ+ตัวอักษร sapphire)
- **M-109-2** — เมื่อเลือก "ต้นฉบับ" การแตะรูปเป็น no-op (`_repositionImage` return ทันทีเมื่อ `ratio == null`)
  แต่ `Semantics(label: 'รูปที่ N กดเพื่อปรับตำแหน่ง', button: true)` ยังบอกว่ากดได้
  → ควรถอด `button: true`/เปลี่ยน label เมื่อเป็นต้นฉบับ
- **M-109-3** — เมื่อเลือก "ต้นฉบับ" `_imageExtensions` ยังถูกตั้งเป็น `'png'` ทั้งที่ byte เป็น JPEG จาก picker
  (เพราะ `_applyRatio` คืนค่าเดิมโดยไม่ encode ใหม่) → object ใน Storage ได้ `Content-Type: image/png` ผิดความจริง
  แอปยัง render ได้เพราะ decoder sniff เอง แต่ header ผิดควรแก้ให้ตรง
- **M-109-4** — ครอปที่ผู้ใช้ลากเลือกเองถูกทิ้งเงียบ ๆ เมื่อเปลี่ยนชิปทีหลัง
  (มี comment อธิบายเหตุผลไว้แล้วและสมเหตุสมผล แต่ควรมี snackbar/ข้อความบอกผู้ใช้)
