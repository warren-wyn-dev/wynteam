## ผลข้อมูลจริงจาก WYN Admin Dashboard (2026-09-06)

Founder เปิดหน้า "การเติบโตและ Retention" ส่งภาพหน้าจอมาให้ ตัวเลขที่เห็น:

- **สมัครใหม่ ใน 24 ชม.ล่าสุด**: 0
- **สมัครสำเร็จ**: 1 คน, อัตราสมัครสำเร็จ (%) แสดง 0 (ปัดเศษลงเพราะฐานเล็กมาก)
- **Activation**: 0 คน
- **D1 Retention**: 0% (นับจากผู้สมัครสำเร็จเมื่อ 2-3 วันก่อน)
- **D7 Retention**: 0% (นับจากผู้สมัครสำเร็จเมื่อ 8-9 วันก่อน)
- **ช่องทางยอดนิยม (7 วันล่าสุด)**: "ยังไม่มีข้อมูลช่องทาง" — dashboard เองระบุว่านับช่องทางได้เฉพาะลิงก์ที่มี **UTM parameter** เท่านั้น

**ตรงตาม Risk ที่ระบุไว้ล่วงหน้าในงานนี้พอดี**: ฐานข้อมูลเล็กเกินกว่าจะฟันธง % ทางสถิติได้จริง (สมัครสำเร็จแค่ 1 คนในช่วงที่วัด, ไม่มี signup เลยใน 24 ชม.ล่าสุด) — **ไม่สรุปเกินข้อมูลที่มี** แต่มี 2 ข้อเท็จจริงที่ชัดเจนพอสรุปได้แล้วโดยไม่ต้องรอ sample เพิ่ม:

1. **ไม่เคยมีการติด UTM parameter ในลิงก์ที่แชร์เลยสักครั้ง** — เป็นช่องโหว่ด้าน measurement ล้วนๆ ไม่เกี่ยวกับ sample size: ต่อให้มีคนสมัครเข้ามาอีกกี่ร้อยคนก็ยังตอบไม่ได้ว่าช่องทางไหนได้ผล ถ้ายังไม่เริ่มติด UTM ตั้งแต่ลิงก์ที่แชร์รอบต่อไป
2. **การไหลเข้าของ signup หยุดสนิทในช่วง 24 ชม.ล่าสุด** — คำถามเร่งด่วนกว่าเรื่อง onboarding ตอนนี้คือ "หยุดแชร์ลิงก์ไปหรือยัง" ไม่ใช่แค่ "คนที่สมัครแล้วทำไมเงียบ" เพราะถ้าไม่มีคนเข้าใหม่เลย จะไม่มีทางเก็บ sample เพิ่มให้พอสรุปได้อีก

ตัวเลข Activation/Retention = 0% ของคนกลุ่มเดียวที่มี **สอดคล้องทิศทางเดียวกับที่ Founder รายงานไว้แต่แรก** (เงียบสนิท ไม่ทำ action) แต่ด้วย n=1 ยังถือเป็นหลักฐานยืนยันทางสถิติไม่ได้ — เป็นแค่สัญญาณที่ไม่ขัดแย้งกับสมมติฐานเดิม

**Recommendation (อัปเดต 2026-09-06)**: ก่อนตัดสินใจลงทุนแก้ onboarding ในแอป (ซึ่งยังไม่มีข้อมูลพอยืนยันว่าคือจุดที่ควรแก้จริง) ให้ทำ 2 อย่างนี้ก่อนพร้อมกัน เพราะเป็น prerequisite ของการวัดผลรอบต่อไปไม่ว่าจะเลือกทางไหนต่อ:
1. **แชร์ลิงก์รอบต่อไปทุกครั้งให้ติด UTM parameter เสมอ** (เช่น `?utm_source=facebook&utm_medium=share&utm_campaign=<ชื่อกลุ่ม>`) — เพื่อให้รอบหน้าเห็นข้อมูล "ช่องทางยอดนิยม" จริงเป็นครั้งแรก
2. **แชร์แบบเจาะจง 1-2 ชุมชน niche ตามที่แนะนำไว้เดิมใน `wynos-gtm-roadmap.md` Phase 1** เพื่อให้มี sample ใหม่มากพอ (อย่างน้อย ~20-50 signup) ก่อนกลับมาดูตัวเลข funnel นี้อีกครั้ง — ฐานข้อมูลตอนนี้เล็กเกินกว่าจะฟันธงอะไรเพิ่มได้แล้ว

Status: ยังคง **active** — บล็อกอยู่ที่ Founder action (แชร์ลิงก์รอบใหม่พร้อม UTM) ไม่ใช่งานที่ AI role ใดทำแทนได้ กลับมาวิเคราะห์ต่อเมื่อมี sample ใหม่มากพอ

## แก้ไข (2026-09-06 รอบ 2) — Founder ยืนยัน "ยังแชร์อยู่ตลอด แต่คนไม่เข้ามาเลย" — เปลี่ยนคำถามที่ต้องตอบทั้งหมด

Founder ยืนยันว่า**ไม่ได้หยุดแชร์ลิงก์** — ยังแชร์ต่อเนื่องแต่ signup ยังเป็น 0 ใน 24 ชม. เหมือนเดิม เปลี่ยนสมมติฐานเดิมทั้งหมด: **นี่อาจไม่ใช่ปัญหา onboarding/activation ในแอปเลยด้วยซ้ำ** เพราะปัญหาอาจเกิด**ก่อน**ถึงจุดที่แอปวัดอะไรได้เสียอีก

**พบข้อจำกัดสำคัญของระบบ analytics ปัจจุบันระหว่างตรวจโค้ด** (`supabase/schema.sql` ตาราง `analytics_events`, comment บรรทัด ~7528): event แรกสุดที่ระบบเก็บคือ `signup_started` ซึ่ง **fire หลังจาก Supabase auth account ถูกสร้างสำเร็จแล้วเท่านั้น** (`user_id` เป็น NOT NULL อ้าง `auth.users`) — ตรวจ `app/web/index.html` เพิ่มเติมยืนยันว่า**ไม่มี Vercel Web Analytics/Google Analytics หรือ pre-signup page-view tracking ใดๆ ติดตั้งอยู่เลย** สรุปคือ **WYN มองไม่เห็นเลยว่ามีคนคลิกลิงก์/เปิดหน้าเว็บกี่คน** ก่อนจะถึงขั้นตอนสมัคร — `signup_started_24h = 0` เลยตีความได้ 2 ทางที่ต่างกันมากและ WYN เองแยกไม่ได้จากข้อมูลที่มี:

1. **แทบไม่มีคนคลิกลิงก์เข้ามาเลยจริงๆ** (ปัญหาการเข้าถึง/reach บนแพลตฟอร์มที่แชร์ — คนละเรื่องกับตัวโปรดักต์ WYN แก้โค้ดไม่ช่วย)
2. **มีคนคลิกเข้ามาจริง แต่หน้าเว็บ/ปุ่มสมัครมีปัญหาจนไม่มีใครสร้างบัญชีสำเร็จเลยสักคน** (บั๊กจริงในแอป — ต้องส่ง AI Debug Engineer ด่วนที่สุด เพราะถ้าจริงคือบั๊กที่บล็อกคนเข้าใหม่ทุกคน 100%)

**วิธีแยก 2 กรณีนี้โดยไม่ต้องเขียนโค้ดเพิ่มเลย**: ให้ Founder เช็ค**ตัวเลขคลิกลิงก์/reach ที่แพลตฟอร์มที่แชร์แสดงเอง** (เช่น Facebook Insights ของโพสต์นั้นแสดงจำนวนคลิกลิงก์ได้ถ้า Founder เป็นแอดมินเพจ/กลุ่ม) — ถ้ามีคลิกจริงหลายสิบ/ร้อยครั้งแต่ signup = 0 ทั้งหมด แปลว่าเป็นบั๊ก P0 ต้องรีบสืบทันที ถ้าคลิกก็แทบไม่มีเหมือนกัน แปลว่าเป็นปัญหาการเข้าถึงคนละชั้นกับตัวแอปทั้งหมด

Handoff อัปเดต: รอ Founder เช็คตัวเลขคลิก/reach จากแพลตฟอร์มที่แชร์แล้วส่งกลับมา — ถ้าพบว่ามีคลิกแต่สมัครไม่สำเร็จเลยสักคน ให้ส่งต่อ **AI Debug Engineer ทันทีเป็น P0** (ตรวจ signup flow ทั้งเส้นทางบน production จริง ไม่ใช่แค่ local)

## แก้ไข (2026-09-06 รอบ 3) — แพลตฟอร์มที่แชร์ก็ไม่มี insight เรื่องคลิกให้ดู

**Recommendation**: ใช้ **link shortener ที่มี click analytics ในตัว** (เช่น Bitly/T.ly/similar ฟรี) ห่อลิงก์ `wynos.online` ก่อนแชร์รอบถัดไปแทนลิงก์ตรง — **ไม่ต้องแก้โค้ดแอปเลยสักบรรทัด ไม่ต้องรอ dev/deploy ทำได้วันนี้เลย** พอแชร์รอบหน้าจะเห็นทันทีว่ามีคนคลิกกี่ครั้งเทียบกับ signup ที่เกิดขึ้นจริง — ถ้าคลิก > 0 แต่ signup ยังเป็น 0 คือบั๊ก P0 ยืนยันได้ทันที ถ้าคลิกก็ใกล้ 0 เหมือนกันคือปัญหาการเข้าถึง/reach ไม่เกี่ยวกับโค้ด WYN

**ทางเลือกรอง (ใช้เวลานานกว่า)**: เพิ่ม pre-signup page-view event ในระบบ analytics ของ WYN เอง (ตอนนี้เก็บได้แค่หลังมีบัญชีแล้วเท่านั้น) — ต้องแก้ schema (`user_id` เป็น nullable หรือตารางแยกสำหรับ anonymous session) + ส่งผ่าน AI Design/Coding เต็มรูปแบบ ใช้เวลาเป็นวัน ไม่ทันความเร่งด่วนตอนนี้ — เก็บไว้เป็น backlog แยกถ้า Founder อยากให้มี baseline วัดระยะยาว แต่ไม่ใช่ทางแก้ปัญหาเฉพาะหน้ารอบนี้

Handoff อัปเดต: Founder ลองห่อลิงก์ด้วย shortener แล้วแชร์รอบถัดไป ส่งตัวเลขคลิกกลับมาเทียบกับ signup ที่เกิดขึ้นจริง — จะรู้ทันทีว่าควรส่งต่อ AI Debug Engineer (ถ้ามีคลิกจริง) หรือเป็นเรื่องช่องทาง/content ที่ต้องแก้นอกแอป (ถ้าคลิกก็แทบไม่มี)
