# Feature Request — WYN-125

Status: active — Design เสร็จแล้ว, **Coding ห้ามเริ่มจนกว่า WYN-124 สร้างเสร็จก่อนเสมอ**
Owner: AI Product Manager → AI Design

Feature: Presence — เห็นว่าสมาชิกคนไหนกำลังออนไลน์อยู่ในห้องแชทกลุ่มของ Club ตอนนี้บ้าง (ต่อยอด WYN-124)

Goal: เพิ่มความรู้สึก "ที่นี่มีคนอยู่จริงตอนนี้" ให้ห้องแชทกลุ่ม — จุดเขียวข้างชื่อแบบ Discord คือสัญญาณ "server active" ที่ทำให้คนกลับมาเปิดซ้ำ ต่างจากแค่เห็นประวัติข้อความเก่าเฉยๆ

Target User: สมาชิก Club ที่เปิดห้องแชทกลุ่ม (WYN-124) อยากรู้ว่าตอนนี้มีใครอยู่บ้างก่อนจะทัก

Problem: WYN-124's ห้องแชทกลุ่ม (design เสร็จแล้ว ยังไม่ได้สร้าง) ไม่มีกลไกบอกสถานะออนไลน์เลย เห็นแค่ประวัติข้อความ ไม่รู้ว่าใครกำลังใช้งานจริงตอนนี้

## Requirements

### R1 — ขอบเขตเฉพาะ Club Group Chat เท่านั้น ไม่ใช่ presence ระดับแอป
ไม่ทำ "online ทั่วแอป" แบบ Facebook — แค่ "กำลังเปิดหน้าห้องแชทกลุ่มของ Club นี้อยู่หรือไม่" เท่านั้น ตรงกับที่ Founder ย้ำว่า Club ต้องเป็นโลกของตัวเอง ไม่ไปกระทบหน้าแชท 1-ต่อ-1 (DM) เดิม — DM ไม่มี presence อยู่แล้วตอนนี้ และงานนี้ไม่เพิ่มให้ DM ด้วย

### R2 — จุดสถานะที่ avatar ในห้องแชท + subtitle ใน header
จุดเขียวเล็กมุม avatar ของสมาชิกที่ online ในรายการข้อความ + header ของห้องแชท (ที่ WYN-124 ออกแบบเป็น "ชื่อ Club + N สมาชิก") เปลี่ยนเป็น "N คนออนไลน์" เมื่อมีคน online จริง — ไม่มีใคร online เลยกลับไปแสดง "N สมาชิก" เหมือนเดิมทันที

### R3 — ใช้ Supabase Realtime Presence (ของมีอยู่แล้วในแพลตฟอร์ม ไม่สร้างตารางใหม่)
"online" = กำลังเปิดหน้าห้องแชทกลุ่มนี้ค้างอยู่จริง (ผูกกับ presence channel ตอนเข้าหน้า) ไม่ใช่ last-seen แบบหยาบ — ปิดหน้า/ออกจากห้อง = offline ทันทีผ่าน disconnect ของ presence channel เอง ไม่ต้องเขียน logic timeout เอง

### R4 — ไม่กระทบ Unread badge/Mute ที่ WYN-124 ออกแบบไว้แล้ว
Presence เป็นแค่ signal เสริมที่แสดงผล ไม่เปลี่ยนพฤติกรรม unread count หรือ notification ใดๆ ที่มีอยู่แล้ว

## Acceptance Criteria

1. เปิดห้องแชทกลุ่ม เห็นจุดเขียวที่ avatar ของสมาชิกที่กำลังเปิดหน้าเดียวกันอยู่จริงในขณะนั้น
2. ปิดหน้า/ออกจากห้อง สถานะเปลี่ยนเป็น offline ให้คนอื่นเห็นได้ภายในไม่กี่วินาที ไม่ต้อง refresh
3. ไม่มีใคร online เลย → header กลับไปแสดง "N สมาชิก" ทันที ไม่ค้างคำว่า "0 คนออนไลน์"
4. หน้าแชท 1-ต่อ-1 (DM) และ Home Feed ไม่ถูกแตะเลยแม้แต่จุดเดียว

## Dependencies

- **WYN-124 (Club Group Chat) ต้องสร้างเสร็จก่อนเสมอ** — presence อยู่ในหน้าห้องแชทกลุ่มที่ WYN-124 สร้าง ไม่มีห้องก็ไม่มีที่ให้ presence แสดง
- Supabase Realtime Presence — ฟีเจอร์ของแพลตฟอร์มที่มีอยู่แล้ว ไม่ต้องเพิ่มตาราง/schema ใหม่ฝั่ง DB

## Priority

P3 — ต่อท้าย WYN-124 ในคิว ไม่เร่งด่วนเพราะ Group Chat เองก็ยังไม่ถูกสร้าง

## Risks

- Scale: Club สมาชิกหลักพันคนเปิดพร้อมกันอาจทำให้ presence channel broadcast ถี่จนหนัก ต้องทดสอบจริงตอน Coding ไม่ใช่แค่เดา
- ต้องระวังไม่ให้ "เห็นว่า online" กลายเป็นแรงกดดันทางสังคม (รู้สึกต้องรีบตอบเพราะถูกเห็นว่า online) — ไม่ใช่ปัญหาเทคนิคแต่เป็นเรื่อง tone ที่ Design ควรพิจารณา — **ไม่ทำ "กำลังพิมพ์..." เพิ่มในรอบนี้** เพื่อคุม scope ไม่ให้บานปลาย

## Recommendation

ทำหลัง WYN-124 deploy จริงและเห็นว่าห้องแชทกลุ่มมีคนใช้งานจริงก่อน — presence ไม่มีประโยชน์ถ้ายังไม่มีห้องให้เกิด "การมีอยู่จริง" ขึ้นก่อน ระหว่าง WYN-125/126 (Chat Reaction) ไม่มี dependency ต่อกัน ทำก่อน-หลังกันได้อิสระ แต่ effort ต่ำกว่าเพราะใช้ของที่แพลตฟอร์มมีให้แล้ว จึงแนะนำให้ทำก่อน WYN-126

## Handoff (Product → Design)

ส่งต่อ **AI Design** ออกแบบ UX ของจุดสถานะ/header subtitle ได้ตอนนี้เลยถ้า Founder ต้องการ — **AI Coding ต้องรอ WYN-124 สร้างเสร็จก่อนเสมอ**
