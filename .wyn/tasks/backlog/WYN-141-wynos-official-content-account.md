# Product Task — WYN-141

Status: backlog
Owner: AI Product Manager
Feature: บัญชีทางการของ WYNOS (Official Account) สำหรับ Content Seeding แก้ปัญหา Feed ว่างเปล่า
Goal: ให้ผู้ใช้ใหม่ที่เปิดแอปครั้งแรกเห็นว่า WYNOS "มีชีวิต" จริง ไม่ใช่แอปร้าง ก่อนที่ organic content
  จากผู้ใช้จริงจะมีมากพอ — ลด first-impression ที่แย่ที่เป็นสาเหตุหนึ่งของปัญหาที่ WYN-112 เจอ (สมัครแล้ว
  เงียบสนิท ไม่กลับมาเปิดแอปอีก)
Target User: ผู้ใช้ใหม่ที่เพิ่งสมัคร/เปิดแอปครั้งแรก โดยเฉพาะช่วง cold-start ตอนนี้ที่แทบไม่มี organic
  content เลย (WYN-112: สมัครสำเร็จแค่ 1 คนในช่วงที่วัด, Activation/Retention 0%)
Problem: จาก WYN-112 พบว่า feed "สำหรับคุณ" ของผู้ใช้ใหม่แทบว่างเปล่า เจอ empty state "ยังไม่มีใครโพสต์
  อะไรเลย เป็นคนแรกสิ!" ทันทีที่เปิดแอปครั้งแรก — first impression แบบนี้สื่อว่าแอปไม่มีคนใช้จริง/ตายแล้ว
  เป็นสาเหตุที่น่าเชื่อได้ว่าทำให้คนสมัครแล้วไม่กลับมาเปิดแอปอีกเลย (ตรงกับ D1/D7 retention 0% ที่ WYN-112
  วัดได้) — เอกสาร GTM roadmap เดิม (`wynos-gtm-roadmap.md` Phase 1) เคยแนะนำเรื่อง "content seeding" ไว้แล้ว
  ก่อนเริ่ม Phase 1 closed beta แต่ยังไม่เคยถูกทำจริง
Requirements:
- สร้างบัญชี WYNOS ทางการ 1 บัญชี (เช่น username `wynos`) ที่ระบุตัวตนชัดเจนว่าเป็นบัญชีของทีม/แพลตฟอร์ม
  เอง ไม่ใช่ผู้ใช้ทั่วไป — ไม่ใช่บัญชีปลอมที่แกล้งทำเป็นผู้ใช้ทั่วไป (Founder ยืนยันแนวทางนี้แล้ว 2026-09-08)
- Bio ของบัญชีต้องบอกชัดว่าเป็นบัญชีทางการของทีม WYNOS
- เนื้อหาที่โพสต์: อัปเดตแพลตฟอร์ม, feature highlight, เคล็ดลับการใช้งาน, แนะนำ Club/คอนเทนต์เด่นที่มีอยู่
  จริง — ไม่ใช่คอนเทนต์ที่แกล้งทำเป็นการพูดคุยส่วนตัวของผู้ใช้ทั่วไป
- โพสต์โดยคนจริง (Founder หรือทีม) ไม่ใช้ automation/bot สร้างเนื้อหาอัตโนมัติในเวอร์ชันแรก เพื่อคุมคุณภาพ
  และความน่าเชื่อถือของเนื้อหา
- ตรวจสอบว่าระบบ Verified Badge ที่มีอยู่แล้ว (WYNOSHomeSpec.md 4.9, `wyn-v1.0.0-master-spec.md`) ใช้เป็น
  ตัวบ่งชี้ "บัญชีทางการ" ได้เลยหรือไม่ ก่อนพิจารณาสร้างตัวบ่งชี้ใหม่
Acceptance Criteria:
- มีบัญชีทางการ 1 บัญชี ระบุตัวตนชัดเจนว่าเป็นทีม WYNOS ในหน้า Profile (bio อย่างน้อย)
- ผู้ใช้ใหม่ที่ยังไม่ follow ใคร/ไม่มี Club เห็นโพสต์จากบัญชีนี้ในแท็บ "สำหรับคุณ" แทนที่จะเจอ empty state
  ทันทีที่เปิดแอปครั้งแรก
- โพสต์สม่ำเสมอตามความถี่ที่ Founder กำหนด (ดู Handoff) — ไม่ใช่โพสต์ครั้งเดียวตอนสร้างบัญชีแล้วทิ้ง เพราะ
  timestamp เก่ามากจะยิ่งดูเหมือนแอปถูกทิ้งร้างกว่าไม่มีเลย
Dependencies: ไม่มี dependency ทางเทคนิคใหม่สำหรับเวอร์ชันแรก — ใช้ระบบสมัครบัญชี/โพสต์ Drop-Pop ที่มีอยู่
  แล้วทั้งหมด ถ้า Verified Badge เดิมใช้เป็นตัวบ่งชี้ "บัญชีทางการ" ได้เลย ก็ไม่ต้องมี AI Design/Coding
  เพิ่มเลย — Founder สร้างบัญชีเองได้ทันที ต้องรอ AI Design เฉพาะกรณีต้องการตัวบ่งชี้ "Official" แบบใหม่ที่
  ต่างจาก Verified Badge เดิม
Priority: P1 — ตรงกับปัญหา cold-start ที่ WYN-112 ยืนยันแล้วว่าเกิดขึ้นจริง เป็นทางแก้ที่ทำได้เร็วที่สุด
  (ไม่ต้องรอ dev) เทียบกับทางเลือกอื่นที่ WYN-112 เสนอไว้ (invite-gate แบบเจาะจง niche community)
Risks:
- **ความน่าเชื่อถือ**: ถ้าไม่ระบุตัวตนชัดว่าเป็นบัญชีทางการตั้งแต่แรก ผู้ใช้อาจรู้สึกถูกหลอกภายหลังถ้ามารู้
  ทีหลังว่าเป็นบัญชีของทีมเอง ไม่ใช่ผู้ใช้จริง — บัญชีเดียวที่ transparent ตั้งแต่ต้นไม่เจอปัญหานี้ (ต่างจาก
  บัญชีสมมติหลายบัญชีที่แกล้งเป็นผู้ใช้ทั่วไป ซึ่ง Founder เลือกไม่ทำแนวทางนั้นแล้ว)
- **แก้ปัญหาได้แค่บางส่วน**: บัญชีเดียวไม่พอแก้ปัญหา "รู้สึกว่าแอปมีคนใช้จริงเยอะ" ในระยะยาว เป็นแค่ plug
  the empty feed ระยะสั้น ไม่ได้แก้สาเหตุที่ organic user ไม่กลับมาใช้งานต่อ (คนละปัญหากับที่ WYN-112 กำลัง
  สืบอยู่) — ควรทำคู่กับ content seeding จาก Founder+ทีมด้วยบัญชีจริงของตัวเอง ตามที่ GTM roadmap เดิมเคย
  แนะนำไว้แล้ว เพื่อให้ feed ดูมีคนจริงหลากหลาย ไม่ใช่มีแค่ 1 บัญชีเดียว
- **ความสม่ำเสมอ**: ถ้าโพสต์ไม่ต่อเนื่อง (สร้างแล้วทิ้ง) จะแย่กว่าไม่มีบัญชีนี้เลย เพราะเห็น timestamp เก่า
  มาก ยิ่งตอกย้ำว่าแอปถูกทิ้งร้าง — ต้องมีแผนความถี่จริงที่ทำได้ต่อเนื่อง ไม่ใช่แค่ตั้งใจไว้ตอนแรก
- **คุณภาพเนื้อหา**: ถ้าโพสต์คุณภาพต่ำ/ดูเป็นการยัดเยียด (spam-like) จะยิ่งลด trust แทนที่จะช่วย
Recommendation: เริ่มจากบัญชีทางการ 1 บัญชี (username `wynos` หรือใกล้เคียง) โพสต์โดย Founder เองเป็นคนจริง
  ไม่ใช้ automation อย่างน้อยสัปดาห์ละ 2-3 ครั้ง เนื้อหาเน้น "ยินดีต้อนรับ", "แนะนำฟีเจอร์ที่มีอยู่", "อัปเดต
  จากทีม" — ใช้ Verified Badge เดิมถ้าตรวจสอบแล้วใช้แทน "Official" indicator ได้ (ประหยัดเวลา ไม่ต้องรอ Design/
  Coding เลย) — ทำคู่ขนานกับที่ GTM roadmap เดิมแนะนำไว้แล้ว (Founder+ทีมโพสต์ด้วยบัญชีจริงของตัวเองด้วย
  ไม่ใช่พึ่งบัญชีทางการอย่างเดียว) เพื่อให้ feed ดูมีคนจริงหลากหลายตั้งแต่วันแรก ไม่ใช่ทางแก้ retention ระยะ
  ยาว แต่เป็น prerequisite ที่ทำได้ทันทีก่อนจะลงทุนแก้จุดอื่นตาม WYN-112
Handoff: Founder ตัดสินใจ 3 เรื่องก่อนเริ่มได้จริง — (1) ต้องการตัวบ่งชี้ "Official" ใหม่ หรือใช้ Verified
  Badge เดิม+bio พอ (2) ความถี่โพสต์ที่ตั้งใจทำได้จริงต่อเนื่อง (3) ใครเป็นคนโพสต์ (Founder คนเดียว หรือมี
  คนอื่นช่วย) — ถ้าใช้ Verified Badge เดิมพอ Founder สร้างบัญชีเองได้ทันทีวันนี้ ไม่ต้องรอทีม AI ทำอะไรเพิ่ม
  เลย ถ้าต้องการตัวบ่งชี้ใหม่ ส่งต่อ AI Design ออกแบบต่อ
