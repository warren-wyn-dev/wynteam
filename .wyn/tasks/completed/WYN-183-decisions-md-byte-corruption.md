# Product Task — WYN-183

Status: active
Owner: AI Product Manager / AI Database Engineer (investigation)
Feature: แก้ไข byte corruption ใน `.wyn/company/DECISIONS.md` (company decision log)
Goal: จัดการช่วงต้นไฟล์ `.wyn/company/DECISIONS.md` ที่เสียหายระดับ byte ให้เหมาะสม — ตามที่ AI Coding พบระหว่างทำ WYN-182 และ Founder สั่งเปิดงานแยก

## Investigation (ตรวจจริงแล้ว 2026-09-20)

**สรุปสั้น: เนื้อหาส่วนนี้กู้คืนไม่ได้แล้ว — ไม่ใช่ปัญหาที่ "แก้" ได้ในความหมายปกติ**

1. **ขอบเขตความเสียหาย**: บรรทัด 1-618 จากทั้งหมด 2,443 บรรทัด (~25.3% ของไฟล์) เป็น byte sequence `\xef\xbf\xbd` (U+FFFD REPLACEMENT CHARACTER) แทรกอยู่ 14,139 ครั้ง ปนกับอักขระ ASCII/สัญลักษณ์บางตัวที่หลุดรอด — อ่านไม่ได้เป็นข้อความเลยแม้แต่ประโยคเดียว
2. **ยืนยันว่าเป็น byte-level corruption จริง ไม่ใช่แค่ font/terminal display issue**: ตรวจ raw bytes ด้วย `od -c` ยืนยันตัวไฟล์เองมี byte sequence ของ U+FFFD ฝังอยู่จริง (ไม่ใช่แค่ render ผิดตอนแสดงผล)
3. **ไม่มี header (`## [YYYY-MM-DD] ...`) หลงเหลืออยู่ในช่วงที่เสียหายเลยแม้แต่อันเดียว** (`grep -c "^## \["` = 0 ในบรรทัด 1-618) — ไม่มีร่องรอยว่าเคยมีกี่ entry, วันที่อะไร, หรือหัวข้ออะไรบ้าง
4. **ตรวจ git history ทั้งหมดของไฟล์ (77 commits ที่แตะไฟล์นี้) — ไม่มีเวอร์ชันไหนใน git ที่ยังไม่เสียหายเลย**: ไล่กลับไปถึง commit แรกสุดที่สร้างไฟล์นี้ (`d3607a30`) ก็พบว่าเสียหายอยู่แล้วตั้งแต่ commit แรกสุด — สรุปว่าความเสียหายเกิดขึ้น**ก่อน**ไฟล์นี้ถูก commit เข้า git ครั้งแรก (เช่น เขียนไฟล์ด้วย encoding ผิดตั้งแต่ต้น หรือ copy-paste จากแหล่งที่ decode ผิดมาก่อน) — **ไม่มีทางกู้คืนเนื้อหาเดิมจาก git ได้เลย**
5. เนื้อหาหลังบรรทัด 618 เป็นภาษาไทยปกติสมบูรณ์ อ่านได้ 100% (เริ่มกลางประโยคพอดีเกี่ยวกับ `wyn115-apply-club-poll-schema.yml`) — ส่วนนี้ (74.7% ของไฟล์) ไม่มีปัญหาอะไร ไม่ต้องแตะ

## ทางเลือกสำหรับ Founder (ตัดสินใจได้ ไม่มีทางเลือกไหนที่ "ถูกต้องเพียงทางเดียว")

**A. ปล่อยไว้ตามเดิม ไม่แก้อะไร** — เก็บ byte corruption ไว้เป็นหลักฐานทางประวัติศาสตร์ของไฟล์ (git blame ยังสืบได้ว่าเสียหายมาตั้งแต่ commit แรก) ข้อเสีย: เปิดไฟล์แล้วเจอ mojibake รกสายตา, เครื่องมือบางตัว (เช่น search/grep แบบ UTF-8 strict) อาจสะดุด

**B. ลบส่วนที่เสียหาย (บรรทัด 1-618) ออก แทนที่ด้วยหมายเหตุสั้นๆ อธิบายว่ามี decision log ช่วงต้นที่เสียหายกู้คืนไม่ได้ พร้อมช่วงวันที่โดยประมาณ (ก่อน commit `d3607a30`)** — ไฟล์อ่านง่ายขึ้น สูญเสีย "หลักฐานดิบ" ของความเสียหายไป (แต่กู้คืนไม่ได้อยู่แล้วไม่ว่าจะเก็บ raw bytes ไว้หรือไม่)

**C. เหมือน B แต่ย้ายส่วนที่เสียหายไปเก็บเป็นไฟล์ archive แยก (เช่น `.wyn/company/DECISIONS-corrupted-preamble.md.bak`) แทนที่จะลบทิ้งเลย** — ไฟล์หลักอ่านง่าย + ยังเก็บ raw evidence ไว้เผื่อมีเครื่องมือกู้ข้อมูลในอนาคต (แม้จะไม่มีในตอนนี้)

**คำแนะนำ**: ตัวเลือก **C** — ปลอดภัยที่สุด (ไม่ทำลายอะไรถาวรเกินกว่าที่เสียหายไปแล้ว, ย้อนกลับได้ถ้า Founder เปลี่ยนใจ) และทำให้ไฟล์หลักที่ทีมใช้งานจริงทุกวันอ่านง่ายขึ้นทันที

## Requirements (เมื่อ Founder เลือกแล้ว)

- ถ้าเลือก B/C: ห้าม rewrite git history เดิม (ตาม Git Safety ใน AGENTS.md) — ทำเป็น commit ใหม่ตามปกติเท่านั้น ของเดิมยังอยู่ใน git log ให้สืบย้อนได้เสมอ
- เพิ่ม root-cause note ในไฟล์ (หรือไฟล์ archive) อธิบายว่าเสียหายมาตั้งแต่ก่อน commit แรกที่มีไฟล์นี้ ป้องกันคนงงในอนาคตว่าทำไมมี "รู" อยู่ในประวัติศาสตร์การตัดสินใจของบริษัท
- ไม่ต้องมี QA/Deploy gate (ไม่ใช่ application code ไม่กระทบ production runtime) — แค่ commit + push ตามปกติ
